# Qwen3-VL-2B · Q4_K_M 一键部署（llama.cpp）

双击 **一键部署.bat** 即可。首次会下载运行时和模型（约 2.4 GB），之后每次启动几秒。

---

## 这套包会做什么

| 步骤 | 内容 |
| --- | --- |
| 1 | 检查 64 位、磁盘空间、NVIDIA 驱动、CUDA 版本、端口占用 |
| 2 | 准备 llama.cpp 运行时（优先复用本机已有的 `llama.cpp`；没有就从 GitHub 加速镜像下载 win-cuda 版） |
| 3 | 从 `hf-mirror.com` 下载 `Qwen3-VL-2B-Instruct-Q4_K_M.gguf`（1.1 GB）+ `mmproj-F16.gguf`（0.8 GB） |
| 4 | 生成随机 API Key 写入 `api-key.txt` |
| 5 | 启动 `llama-server`，等 `/health` 返回 ok，把接入信息写进 `api-info.txt` |

## 文件说明

```
Qwen3-VL-2B-Q4_K_M一键部署\
├─ 一键部署.bat      首次用：装环境 + 下模型 + 启动（平时点这个）
├─ 一键部署-重新下载运行时.bat  从零复现用：连 llama.cpp 也重下（一般点不到）
├─ 启动.bat          平时用（部署过一次之后）
├─ 停止.bat          结束服务、释放显存
├─ 状态.bat          看进程 / 端口 / 健康 / 模型 / 显存
├─ 看图.bat          拖一张图片进去，让模型描述（最常用的验证方式）
├─ deploy.ps1        部署与启动的实现
├─ stop.ps1 / status.ps1 / see.ps1
├─ runtime\           llama.cpp（llama-server.exe + CUDA DLL，自动生成）
├─ models\            两个 .gguf（自动生成）
├─ logs\              每次启动的 stdout / stderr
├─ api-key.txt        API Key（生成后固定不变）
├─ api-info.txt       接入信息（地址、模型名、Key、curl 示例）
└─ server.pid         正在跑的进程号
```

## 两个一键部署的区别

| 文件 | 运行时从哪来 | 什么时候点 |
| --- | --- | --- |
| `一键部署.bat` | **优先复用**本机已有的 `llama.cpp`（本机就是 `D:\1\Qwen3.5-9B · Q4_K_XL\llama.cpp`），没有才下载 | 平时都用这个，少下约 560 MB |
| `一键部署-重新下载运行时.bat` | **强制**从 GitHub 镜像下一份新的 llama.cpp（约 560 MB），无视本机已有的 | 只想从零复现整套流程，或本机那份坏了 |

两个点下去之后做的事完全一样：检查环境 → 备运行时 → 下模型 → 生成 Key → 启动 → 自检。
`-Runtime reuse` 强制只用本机那份（没有就报错），`-Runtime <目录>` 可指定现成运行时目录。

## 服务地址

- 接口：`http://127.0.0.1:8091/v1`（OpenAI 兼容）
- 模型名：`qwen3-vl-2b-q4km`
- 网页试玩：浏览器打开 `http://127.0.0.1:8091/`，API Key 填 `api-key.txt` 里的值
- 健康检查：`http://127.0.0.1:8091/health`（不需要 Key）

> 两套包用的端口不同（BF16 是 8090、这套是 8091），所以可以同时装、同时跑、互不影响。

## 为什么是 Q4_K_M

Q4_K_M 是 4 bit 的"甜点档"：体积约为 BF16 的 1/3，速度更快、显存更省，而质量损失在 2B 这个尺寸上很小——日常看图说话、OCR、文档问答够用。
要做精细判断（表格结构、细小文字）时换 BF16 那套更稳。

## 常见问题

- **想完整复现一次（连运行时也重新下）**：双击 `一键部署-重新下载运行时.bat`，它会忽略本机已有的 llama.cpp，走 GitHub 镜像下 win-cuda 运行时。
- **启动卡在"等待模型加载"**：看 `logs\server-*.err.log` 最后 20 行；显存不够会直接 OOM。
- **下载断了**：直接重跑，脚本用 `curl -C -` 断点续传。
- **GitHub 下不动**：脚本按 `gh-proxy.com → ghfast.top → ghproxy.net → 直连` 顺序试；都不行就手动下 `llama.cpp` 的 `win-cuda` 压缩包，解压到 `runtime\` 后重跑。
- **换端口**：改 `deploy.ps1` 顶部的 `$Port`，同时改 `stop.ps1` / `status.ps1` 里同名变量。
- **想换别的量化**：把 `$ModelFile` 改成仓库里别的文件名即可（`Qwen3-VL-2B-Instruct-Q8_0.gguf` 等）。

## 摄像头识别

包里带了一个本地网页，打开浏览器就能用摄像头拍照、直接让模型描述画面。

1. 先双击 `一键部署.bat`（或 `启动.bat`），等它输出「服务已就绪」——识别要靠这个服务。
2. 双击 `摄像头识别.bat`：会起一个小后端并自动打开 `http://127.0.0.1:8093/`。
3. 页面上点「打开摄像头」→「拍照并识别」。可以改上面的提问再点「用这张图再问一次」。
4. 拍过的照片会自动存到包里的 `shots\` 目录。

说明：
- 关掉那个黑色命令行窗口就等于关掉这个网页服务；模型服务不受影响，仍可用 `停止.bat` 单独停。
- 浏览器要允许摄像头权限。如果提示打不开摄像头，多半是别的程序占着（同一台机器同一时刻只有一个程序能独占摄像头），也可能是 Windows 设置 → 隐私和安全性 → 相机 里没有放行浏览器。
- 页面和小后端是纯本地回的（浏览器 → 127.0.0.1 的小后端 → 127.0.0.1 的模型服务），不经过任何外网。

## 盲人导航识别（无障碍版）

双击 **`盲人导航识别.bat`**，浏览器会打开深色大字的页面：后置摄像头取景，****说完一句再去抓下一帧**（不会抢话、不会重叠念），把看到的东西念出来**（系统语音，中文）。手机/平板开热点连同一个局域网也能用（把地址里的 127.0.0.1 换成电脑 IP）。

页面上的五个快捷问题：

| 按钮 | 问的是什么 |
| --- | --- |
| 前面能走吗 | 正前方有没有挡路的、要不要绕 |
| 能过马路吗 | 有没有斑马线、信号灯 |
| 红绿灯颜色 | 有信号灯才说颜色，没有就说没看到 |
| 路沿台阶 | 脚下、前方的台阶/路沿/坑/井盖 |
| 找入口 | 要进的门往哪边走 |

**「能不能走」的结论由代码给，不交给模型。**
实测 2B 模型会把提示词里的安全词直接复读成答案（提示词写「红绿灯」，它就在没有路口的照片上说「绿灯，读秒 30 秒」；写「不能走」就永远答「看不清，不能走」）。所以提示词只要求模型做**中性事实描述**（正前方有什么、离多近），前缀由页面按关键词规则加：「可能没看清：」/「注意：」/「可以走：」，都没匹配到就默认「注意：」。

**性能开销（RTX 5070 Ti Laptop 12 GB 实测，960x540 帧）**

| 指标 | Q4_K_M |
| --- | --- |
| 启动到 /health ok | 5.2 秒 |
| 显存 | 1729 → 5992 MiB（净增约 4.3 GB） |
| 进程 RSS | 1545 MB |
| 每帧耗时（含图像编码） | 530–700 ms |
| 同图再问（命中缓存） | 66–240 ms |
| 生成速度 | 118–200 tok/s |
| 磁盘 | models 1838 MB + runtime 6403 MB |

**安全提醒**：这是辅助工具，不是导盲设备。它只描述摄像头拍到的画面，量不出精确距离、听不到车声、也看不到视野外的东西。带出门必须配合盲杖、导盲犬或陪护人；过马路以语音信号灯和车流声为准。
## 手机摄像头识别

> **实时画面**：页面上的画面走 `/stream`，是把手机 MJPEG 原样转给浏览器，看到的是连续视频（实测约 25–30 fps），不是一张张刷新的照片。
> 电脑侧只跟手机保持一条连接（这个 App 同一时间只允许一条），最新一帧会缓存下来，识别时直接取缓存（1–2 ms），所以不会因为"拉流"把识别拖慢。
>
> **连不上先点「自检」**：它会分四层报告——模型服务 / 手机端口 / 认证 / 取帧，哪层打 ✗ 就是哪层的问题。
> 地址只填 `http://10.86.86.232:8081` 也行，服务端会自动试 `/video`、`/shot.jpg` 等常见路径。

**为什么不能在手机上直接打开网页用手机摄像头**：浏览器规定 getUserMedia 只能在 HTTPS 或 localhost 下用。电脑上是 127.0.0.1 所以没事，手机走 http://192.168.x.x:8094 会被直接拒绝（不安全来源）。所以这里改成**电脑去取手机的图**：

1. 手机装一个「IP 摄像头 / IP Webcam」类 App（iPhone 上实测可用的是 **IP 摄像头 Lite for iOS**），打开后它会显示一个地址，形如 http://10.86.86.232:8081。
2. 手机和电脑连同一个 Wi-Fi。
3. 双击本包的 **手机摄像头识别.bat**，浏览器打开 http://127.0.0.1:8095/phone.html。
4. 把地址补成 App 里的**画面地址**：有静态快照的用快照（/shot.jpg、/photo.jpg、/snapshot.jpg），只有实时流的用 MJPEG（常见是 /video、/videostream.cgi）。iPhone「IP 摄像头 Lite」实测是 **http://10.86.86.232:8081/video**（MJPEG），把它填进输入框。
5. 如果页面提示「手机要求登录」，把用户名/密码填进下面那两格。这类 App 默认常是 **admin / admin**（iPhone「IP 摄像头 Lite」实测就是 admin/admin；空的 admin 密码不行）。
5. 连上后点「开始自动识别」，节奏和盲人导航页一样：取一帧 → 念完 → 再取下一帧。

- 地址会记在浏览器本地，下次打开自动填上。
- 取帧走 camera\server.mjs 的 /frame 代理（同源，页面不用碰跨域），代理只接受 JPEG，最大 8 MB，8 秒超时。
- 报「这个地址返回的不是 JPEG」= 填成了实时流地址（MJPEG 流），换成 App 里的快照 / snapshot 地址。
- 手机端能不能被电脑访问：先在同一 Wi-Fi 下用电脑浏览器直接打开那个快照地址试一下，能出图就说明网络通。

**要不要 HTTPS 走手机浏览器直连**：可以，但需要给这个本地服务配证书（自签或局域网的 mkcert），手机还要信任一次证书。目前没做，因为「IP 摄像头 App + 快照」这条不需要证书、也不需要手机浏览器，接哪台手机都行。

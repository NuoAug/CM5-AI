# M2：图片、对象与 OCR 会话

日期：2026-11-03。代码版本 v1.1.25，基于 M1 流式语音及取消修复。只在交互仓库 main 开发，没有更改主控工程或整机配置。本文按“实现 / 验证 / 待办”组织，原有测试数字与限制说明均保留。

## 一、实现

- `VisualContextStore` 按会话保留帧、原始压缩图片、捕获时间、对象视图、ROI、A/B 槽和 OCR 行。单帧不超过 8MiB，所有会话副本总计不超过 16MiB；每会话最多 8 帧、16 对象，每帧最多 128 OCR 行，空闲会话限时释放。
- `/api/eyes`、`/api/ask`、`/api/talk`、最终语音入口使用同一图片桥接。纯聊天不取图；普通追问复用原帧；“现在呢／翻面／重新看”没有新上传图时经正式 FrameProvider 请求新图。新图失败不回退旧图，也不启动独立相机。
- 保留原图给 OCR；VLM 使用同源缩图，已确认对象采用 ROI 副本并返回到原图的坐标映射。原图身份与捕获时间不随裁剪、复用、取回副本刷新。未知拍摄时间的上传图始终标为历史照片。
- A/B 比较向模型传两张有序图片，可交换槽位；已选对象按各自 ROI 裁剪。只配置一个槽位时要求补齐，不静默替代。
- 对象纠正更新所选对象引用，不把旧对象 OCR 搬给新对象。OCR 存原文、位置、分数、帧及识别器；日期、保质期、批号、价格、单位、优惠条件分别表示。未确认归属时保持 `ambiguous`。
- 重复识别仅替换同一来源组。只有显式确认对象及 ROI 后，才能把该 ROI 内、同帧、尚未关联的 OCR 行关联到对象；跨帧、跨对象或越界输入原子拒绝。
- JSON 结果与 SSE 完成事件提供 `frame_context`，包括实际帧、历史属性、对象和比较依据。

## 二、验证

### 2.1 复现与调试入口

在 `CM5-AI/MiniCPM-V4.7-1B/app` 执行：

```powershell
.venv/Scripts/python.exe -X utf8 -m unittest discover -p "test_visual*.py"
```

HTTP 调试入口沿用当前交互 Web 服务地址，不代表主控服务地址。示例请求：

```json
{"task":"scene","session_id":"visual-demo","frame_id":"photo-a","image":"data:image/png;base64,<实际图片>","slot":"A"}
```

先上传后追问：`POST /api/eyes`，`{"task":"followup","session_id":"visual-demo","question":"它是什么颜色"}`。

对象操作：`POST /api/session/visual/action`。例如 `{"session_id":"visual-demo","action":"bind","frame_id":"photo-a","roi_xyxy_px":[10,10,100,100],"name":"所选商品"}`。ROI 必须在实际原图内。随后用 `correct` 和返回的 `visual_target_id` 更换选择；用 `associate_ocr`、`frame_id`、`object_id` 和可选 `row_ids` 明确 OCR 归属。`GET /api/session/visual?session_id=visual-demo` 查看有界元数据。

`slot=A/B` 上传或 `assign_slot` 设置比较对象；`swap` 交换。`new_frame=true` 强制取新图。没有真实主控传输时返回明确不可用；协议替身测试不代表整机已接通。

### 2.2 测试边界与最终回归

测试使用真实小图片字节和明确替身的主控、OCR／VLM响应，覆盖路由、来源、两图输入、ROI及取消竞态。真实模型对照另见 M3 报告，不能把构造路由结果计作视觉质量通过。

最终本地回归：MiniCPM全套331项通过、0跳过；其中图片模块67项、服务器图片入口12项，网页Node回归通过。输入／模型替身性质以各测试说明为准，未将这些计入真人或目标板性能样本。原始日志在该工程被忽略的 test-runs/m2-final-tests.log。

## 三、待办

- 自然语言对象消歧仍需真实多物图序列评测；当前确定性纠正入口需要明确对象 ID／ROI，不宣称已能自动理解任意“不是那个”。
- 商品价签空间关联不明确时保留澄清，未训练自动关联模型。
- 主控真实传输、时钟、连续拍摄、目标板内存、真人交互和长期稳定性仍待验收。

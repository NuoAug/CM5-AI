# 下一阶段优化与实现方案

日期：2026-11-03。状态：待实施方案，不是功能或性能通过报告。
核对基线：3fd6b2bf，工作分支 voice/model-layout-v1.1.22；当前工程 VERSION 为 1.1.22。后续提交遵守仓库 vX.Y.Z 修改内容规范，按已有版本记录顺延。

## 执行顺序

先完成 M1 语音/取消/主控协议闭环，再完成 M2 图片和对象会话；候选许可与运行器预检可以同步准备，正式模型选择在 M3 同题对照后决定。M4 完善数字与自然体验；M5 只针对独立测试证明有收益空间的失败开展有限微调和联合验收。主控服务缺失时使用显式 synthetic/replay 替身，不能自建导航。

## 1. 先修工程瓶颈

| 问题 | 实现落点 | 验证 |
| --- | --- | --- |
| 播报期间停止收音 | 从 device_voice.py 和 DeviceSink 中拆开采集、识别、任务和播放生命周期；AudioInput 持续采集，有界环形缓冲与有界任务队列 | 播放中采集仍运行、任务不会无限堆积、音频欠载与丢块有记录 |
| 整句识别延迟 | 新增 ASR 适配接口，以 sherpa-onnx OnlineRecognizer 原生流式路径对照现整句 Paraformer；保留 partial/final、端点与否定/改口 | 实际语音块增量送入；partial 不执行控制；停顿、否定、改口回归与真人识别测试 |
| 旧回答取消不完整 | DialogueManager 建立 session/turn/request/generation；ModelRunner、TTS、OutputBus、设备写入及完成回调都复查代次 | 取消后注入晚到 token/TTS/回调，旧内容不复活；分别记录静音与后台计算退出 |
| 危险提醒被普通任务阻塞 | MainControlAdapter 独立事件入口，SpeechOutput 唯一播放器；危险事件用独立序号/队列，不随普通 generation 作废 | 普通推理阻塞时仍可处理有效紧急事件；重启/过期/撤销/重复事件不误播 |
| 已入队被当实际发声 | 接齐 PlaybackStatus、OutputCancel、InteractionStatus；区分入队、设备写入、回环实测和播放完成 | 设备断开返回 OUTPUT_UNAVAILABLE；未测首声填 null；取消回执分别说明停声/清队列/计算退出 |

当前 OutputBus 虽有 epoch，但旧生成晚到后可能在入队时取得新 epoch，因此不能把总线取消视为完整请求取消；代次必须由请求起点固定。当前单一 sink worker 同步等待 TTS，紧急提示仍可能等旧合成返回，应拆开合成与唯一设备播放器调度，并使用已就绪的有效紧急短句 PCM。

实现次序为：先打通可测试的取消代次与协议状态机，再接常开采集和流式识别，然后在 XVF3800 与扬声器上验证真实播放参考/AEC、真人语音检测、插话阈值。仅移除 pause() 不构成全双工完成。正常 ASR 与插话检测共享音频输入，但不得因旧问答工作锁而停止接收新音频。

## 2. 回答质量与图片对象

- 将聊天/VQA 调用从 server.py 中抽到 ModelRunner；支持文字、单图、两图、多轮、流式内容和取消能力声明。具体模型模板、停止符、视觉预处理留在模型适配器。
- 纠正 CHAT_RULE 固定两三句、FOLLOW_RULE 固定一两句等过度限制；按问题选择短答/详细解释，先生成完整有效首段再交 TTS。详细请求采用独立输出预算，显式记录 finish_reason=length；必要时续生成，不能把截断当完整答案。
- 历史会话保留真实 role，明确用户与助手身份，加入现有多轮人称混淆失败例；先比较消息结构/提示和上下文截取，再判断是否属于模型能力不足。
- 从正式 FrameProvider 取图，绑定 frame_id、captured_mono_ms、asset、对象引用、ROI 与 OCR 来源。同图追问复用同帧；“现在呢”结合翻面/换图语境取新图；A/B 身份独立，纠正对象时更新引用，不迁移旧 OCR。
- 纯聊天不取图、不视觉编码；低清用于粗场景，OCR 保留高清原图和相关区域。缓存键包含模型版本、帧/内容身份、裁剪与预处理，按字节/帧数/会话长度设上限。
- 空间行动、方向与距离使用带有效期的主控事实；输入分流之外增加输出来源校验，普通 VLM/OCR 文字不能获得主控事实身份。主控事实每段入队与播放前复查有效期。

## 3. VLM 候选与选择

保留 MiniCPM-V 4.7 1B 为基线，优先测试主控建议的 Qwen3.5-0.8B。先核对原始模型和所用转换制品的来源、许可、版本与配套文件，再取得实际需要的一档量化语言权重与视觉组件。Qwen 原始模型和 Unsloth GGUF 是不同发布者的制品，分别记录。

起始候选为 Q4_K_M；若出现有意义质量失败，再用一个较高精度版本区分量化退化与模型能力不足，不一次下载多档。运行器优先评估 llama.cpp，但必须先证明所固定版本的纯文字、单图、两图及模板/停止符/取消路径兼容；不根据上游最新支持推断本地旧二进制已支持。GGUF 可运行不等于 RKNN/RKLLM NPU 已部署。

每轮保持相同应用代码基线、测试集和可比的语义长度要求。比较中文接话、多轮身份、否定/纠正、翻面、两物比较、OCR 事实使用和无法确认时的澄清；同时测有效首声、总时延和整个交互进程集合资源。开发机、目标板，冷/热，回放/真人和纯运行器/端到端分别报告。

只有目标板能运行完整视觉路径，质量门槛通过，且资源/时延有实测收益时，才考虑采用 Qwen。若它中文质量不合格，保留 MiniCPM 并给出失败与必要的更大候选对照，不为参数小而强行切换。模型文件大小不能作为运行 RAM 结论，微调不作为主要降内存办法。

公共语音/协议修复先在基线实现并固定来源 commit，再同步到候选工程并记录来源 SHA；不把两套不同业务代码的结果直接当模型差异。比较时轮流运行一个 VLM；清理本次进程并验证资源回收后再启动下一个，避免重复常驻。实验监听参数显式设置且检查冲突，不修改主控地址或整机设备配置。

此结构是后续实施约定，本次不下载模型、不建立空壳运行版本、不切换默认模型。

## 5. ASR、TTS 与 OCR

- ASR：整句 Paraformer 保留为基线，流式 Paraformer 中英 INT8 作为第一候选；比较否定/改口保留、识别质量、端点等待、CPU/RAM 和整体首声，不把反复整句转写称为原生流式。
- TTS：Piper 先做播放连续性基线；huayan 授权问题保持未闭合。优先对照 MeloTTS 中文 ONNX，分别核代码、权重、ONNX 转换、词典/文本前端许可及离线依赖。比较数字、字母、单位、首段就绪、合成速度和内存，不预先宣布候选更快或已可交付。
- OCR：先保留 RapidOCR/PP-OCR，优化清晰度、高清 ROI 与字段关联，再决定是否换档或训练。保留原文、位置、分数与帧；生产/到期/保质期/批次、价格/单位/条件分开表示。商品与价签对应不明时 ambiguous；关键数字不能由 VLM 补全。

## 6. 性能实验与验收

每次只改变一个主要因素：先测线程 1/2/4，再测上下文 1024/2048 与按需图像档位，前提是不截掉同题必须的语义；记录实际视觉 token 与编码耗时，不按像素比推算加速。固定缓存设置，冷加载与热会话分开；有界音频、文本、图片、TTS 队列，不用 swap 掩盖持续超预算。

首轮准备至少 30 条真人语音、20 组多轮（其中至少 10 组真实视觉序列）、10 组价格/日期对应和 20 次插话/回声/紧急组合；真人/素材许可与独立划分需要实际取得。关键热路径至少 30 次有效样本，报告样本数、失败数、P50/P95，不将 mock/合成驱动当真人通过。

初始目标沿用任务书：热聊天有效首声 P95 争取 ≤2s，同图追问 ≤3s，新图/清晰文字 ≤4s；确认有效插话后停声争取 ≤200ms，另报检测时间。基础常驻约 400—600MiB、整个交互峰值约 1.5—2GiB 都是待实测工程目标。Windows private/working set 与 Linux RSS/PSS 分开，不重复相加；并行主控负载、温度/降频、音频欠载和系统可用资源另测。

独立测试后先做约 30 分钟稳定性，再配合主控进行至少两小时整机热/电池联合验证；最终断外网冷启动必须能加载模型、词典、音色并完成流程，无云端兜底。

## 7. 提交切分与依赖

按可独立审查的工作提交：M1 取消/协议，M1 流式音频与设备验证，M2 帧/对象会话，M3 独立模型候选与对照，M4 OCR/体验，必要的 M5 训练/联合报告。每次 Git 提交与 PR 带版本号，写实际被测 SHA、输入、命令、环境类别、结果与未测项，修复追加原 PR，不把所有重构/换模型/训练合成一个大 PR。

可独立开展：协议状态机、原生流式 ASR 回放、取消晚到注入、图片会话、字段校验、候选许可核查与运行器预检。需要外部条件：真实主控传输参数/时钟与优先级对接、目标板访问、真实 XVF3800 播放参考/麦克风/扬声器、真人语音与照片、主控联合负载及电池验证。缺失部分明确未接入，不用替身补写通过。

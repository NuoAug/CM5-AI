# v1.1.23 原生流式语音与取消链

本阶段在 main 实现并提交，保留 MiniCPM 工程与旧整句识别作为显式基线。没有目标板部署或真人插话通过结论。

## 实际实现

- turns.py 为普通会话固定 session/turn/request/generation；取消或开始新轮后，晚到模型片段、会话写入、TTS结果、PCM和SSE重连旧事件不能恢复旧回答。普通代次与危险优先级分开。
- OutputBus 使用有界普通/紧急合成队列，合成和唯一设备播放器解耦；Piper 支持中止当前进程，新轮可重新加载；危险合成走独立路径，避免等普通TTS锁。队列和单段PCM有上限。
- ALSA 启动前后、每块写PCM前复查取消代次；排空进程仍可被stop找到并终止，旧进程退出不会清除新进程。
- StreamingASR 使用 sherpa-onnx OnlineRecognizer 的原生流，逐块输入，partial仅用于反馈，final才进入会话/控制；超长话语报错，不把截断当最终命令。
- DeviceVoice 保持采集，HTTP请求队列2项、固定2个工作线程；流式最终话语提交 /api/voice/final，不重复做整句ASR。聊天使用真实role历史、有界上下文、完整片段分段播报，结束事件不重播全文。
- 取消回执区分生成线程退出、TTS作业和运行器完成证据。只关闭连接但没有运行器结束证据时 compute_finished 可为null，不能填即时完成。

## 配置与入口

设备模式默认 ASR_BACKEND=streaming-paraformer；独立模型目录通过 ASR_STREAMING_MODEL_DIR 配置，ASR_STREAMING_THREADS 默认为1。缺失模型不自动双常驻或回退旧识别；整句基线需显式设 offline-paraformer。

AEC_REFERENCE_VERIFIED=0 为默认保护策略：播报期间继续读取设备音频，但不让未经去回声验证的音频触发识别/控制。部署方确实验证播放参考与去回声通道后，可声明1，开放持续有声与非空partial共同确认的插话候选链；该开关不是实测凭证，status始终将真人插话标为未测。BARGE_IN_MIN_VOICED_MS 默认200，仍需真人标定。

/api/voice/final 需要 is_final=true、final_transcript 和会话/请求身份，复用旧唤醒、否定、改口与主控路由。控制仍只读有效最终话语；没有主控时明确不可用，不恢复独立导航。旧 /api/voice 继续支持整句WAV基线。

## v1.1.24 复核修复

故障注入发现设备detach→attach后旧准备任务可能播到新播放器，以及重复取消可无限创建连接关闭线程。本次用独立挂载代次和幂等worker限制前者，固定关闭worker与有界队列限制后者；关闭饱和可观测，不能冒充计算已回收。增加Turn.guard_context短临界区供M2提交事实，网络／模型I/O不在该锁中。

新增屏障测试覆盖重挂旧PCM、重复挂载、关闭队列饱和、完成统计及提交守卫。真实声卡、后端计算实际中止和AEC插话仍待设备验收；非流式HTTP在响应头到达前尚不能注册响应关闭，旧输出与状态提交仍受取消代次保护。

# M1 流式语音、取消与主控合同（2026-11-02）

代码版本：`v1.5.0`（M1 阶段交付）。  
合同：`interaction.v0.1`。  
设备：CM5 `EYES`，release `v1.5.0-cm5`；模型与本机发布清单一致。

## 1. 本轮解决的问题

- 旧链路把整段录音送离线 Paraformer，不能边说边识别，也没有临时/最终区分。
- 取消只停止播放，晚到的模型片段仍可能进入输出队列或写入新轮会话。
- 主控不可用时旧实现会启用本地引导；M0 已删除，本阶段保持“明确失败”。

## 2. 实现

### 2.1 原生流式 ASR

- 模型：`sherpa-onnx-streaming-paraformer-bilingual-zh-en`，Apache-2.0，只保留 int8 encoder/decoder/tokens，约 226 MB。
- 模块：`app/stream_asr.py`，懒加载；加载耗时单独记录。
- 接口：
  - `POST /api/asr/stream/start` → `stream_id`
  - `POST /api/asr/stream/chunk`：int16 PCM base64，100 ms 一块，返回临时 `text`
  - `POST /api/asr/stream/end` → 最终 `text`
- 设备端：`device_voice.py` 在 KWS 唤醒后启动流式会话，逐块喂入；VAD 端点后结束并拿最终文本。
- 临时文本只用于内部记录，不进入意图；`/api/voice` 只有在 `final_text=true` 时才执行意图与控制。
- 流式不可用或失败时回退整段离线 Paraformer，并记录失败原因；不把回退伪装成流式。

### 2.2 取消代次

- `OutputBus` 增加 `current_epoch()` / `is_current()` 与 `stale_generation` 计数。
- `push_segment` 可携带 `generation_epoch`；取消后旧 epoch 的片段直接丢弃。
- `/api/talk` 流式生成逐 token 检查 epoch；取消后停止读取、关闭上游流，不再推旧片段。
- `/api/voice`、`/api/eyes` 在模型返回后检查 epoch；旧回答不播放、不写入会话历史。
- 浏览器 SSE 的 `done` 在取消时返回 `cancelled=true` 且 `answer=""`，避免晚到文本复活。

### 2.3 设备语音状态

- `device_voice.status()` 暴露 `asr_stream`：是否启用、是否活跃、已喂块数、临时文本长度。
- `interaction.status.services.asr` 优先报告 streaming Paraformer；不可用时显示 offline fallback。

## 4. 未完成与限制

- 真人“小冰小冰”唤醒率/漏唤醒率未测；合成音频命中不等于真人唤醒率。
- 播报期间仍是半双工暂停采集，真人插话未实现；AEC 实际通道与双讲未验证。
- 设备自播到麦克风的回放未触发 KWS；需要用真人对设备说话复测。
- 流式模型为中英双语，中文专名/数字会出现中英混写；需要在真实语料上评估，必要时加规则或候选模型。
- 首次流式模型加载 2.58 s；按需加载策略与 VLM 峰值内存的联合预算仍需实测。
- 取消能阻止旧片段与旧会话写入，但已发出的 VLM HTTP 请求不能立即中断；后台计算结束时间单独记录，不声称算力已即时回收。
- 语音仍不是全双工，不能宣称“真人插话验收通过”。

## 5. 回滚

- 代码回退到 `v1.4.1`（`0b05e06`）。
- 关闭流式：`ASR_STREAM=0`，设备端回退整段离线 Paraformer。
- 流式模型目录可保留；删除后 precheck 报 WARN，语音回退，不影响聊天与 OCR。

# AI眼镜主控与离线交互接口合同

合同版本：interaction.v0.1  
日期：2026年11月2日  
定义方：AI_Eyes整机主控侧  
实现方：主控侧与语音交互侧，各自实现本侧提供的能力

本合同定义双方必须对应的数据和行为，不表示主控服务已经部署，也不指定现成IP、端口或设备。交互队友先实现适配层和明确标记的开发替身，主控侧实现真实数据提供者后对接。业务语义按本合同执行，内部语言、框架和传输封装可以自行选择；破坏性字段变更须向主控提出版本变更。

## 权限和实现边界

| 提供方 | 对外能力 | 接收方如何使用 |
| --- | --- | --- |
| 主控 | 取图、场景/空间状态、行走控制处理、引导与危险事件、主控健康状态 | 交互侧读取事实并表达，提交用户意图，不自行生成通行授权 |
| 交互 | 用户最终话语及控制意图、视觉目标观测、语音输出/取消、播放与交互健康状态 | 主控接收真实状态、决定控制效果与整机优先级 |
| 开发替身 | 固定的回放/构造状态与错误案例 | 仅验证协议和交互行为，不能作为真实测距、路径或硬件通过证据 |

主控模型类别ID与交互模型类别、商品名称不是同一字典。交互侧消费主控提供的类别名称、语义版本和有效性，不复用SegFormer编号解释主控输出。交互识别出的商品位置不自动获得主控空间目标身份。

以下逻辑消息名与方向固定；可映射为本地函数、Socket消息或HTTP/WebSocket，但在适配层保留同一语义：

| 请求或事件 | 发送方 → 接收方 | 对应结果 |
| --- | --- | --- |
| `capabilities.get` | 双方互查 | `capabilities.result` |
| `frame.acquire` | 交互 → 主控 | `frame.result` |
| `scene.query` | 交互 → 主控 | `scene.result` |
| `control.intent` | 交互 → 主控 | `control.result` |
| `target.observation` | 交互 → 主控 | `target.result` |
| `guidance.event` | 主控 → 交互 | 交互持续反馈 `playback.status`，含入队/丢弃/失败与播放过程 |
| `output.cancel` | 主控 → 交互，或交互内部取消 | `output.cancel.result`，说明停止、清队列和计算退出是否完成 |
| `playback.status` | 交互 → 主控 | 事件反馈，以消息和片段身份去重 |
| `interaction.status.get` | 主控 → 交互 | `interaction.status`；也可协商周期推送同一结构 |

## 传输与时间

建议同一计算盒内采用本地请求/响应通道加常驻事件通道，例如HTTP加WebSocket或本地Socket。普通推理与紧急事件使用独立队列或连接，避免长推理占住唯一通道。端口、路径、Socket位置和心跳间隔放在配置中，禁止以某个默认地址认定已经接入真实主控。

图像通过只读文件、共享内存或本地二进制接口传递，适配层统一访问；不要默认持续将高清帧复制为多份base64 JSON。音频在交互内部流动，不要求主控转发每个音频块。

- 时间单位为毫秒，空间距离单位为米，角度若使用则明确度或弧度，字段名或单位字段保持唯一。不能把毫米读成米、像素宽度读成实际宽度。
- 同一主机用同一单调时钟，握手确认 `clock_id` 与主机启动标识；明确使用同一种时钟来源。每个服务另有 `instance_id`，用于识别进程重启。
- 不同电脑开发时不能直接相减各自单调时钟；需实现时钟映射并报告误差，或仅作回放测试。不能确认时钟对应时，实时距离与行走结论不可用。
- `valid_until_mono_ms` 由主控对实时结果给出。交互侧不得擅自延长；读取和准备播放时都复查。照片可作为历史内容继续讨论，但不会因此变成当前测量。
- 心跳丢失、主控重启、时钟变化或序号倒退时，撤销旧主控状态及其待播行动提示，重新握手后再接收新状态。不能跨重启沿用旧 `state_id`、`track_id` 或通行结论。

## 公共消息字段

| 字段 | 类型和约定 |
| --- | --- |
| `schema_version` | 固定字符串 `interaction.v0.1`；不支持的版本返回明确错误 |
| `type` | 下文逻辑消息名，含请求/响应/事件区分 |
| `message_id` | 本条消息的唯一字符串ID；重发同条事件不改变ID |
| `reply_to` | 响应对应的请求 `message_id`；请求与普通事件为null |
| `request_id` | 一次业务请求的幂等ID，响应保持相同；独立系统事件可为null |
| `session_id` | 交互会话ID；无会话的主控事件为null，不能借用默认会话串到另一用户 |
| `producer` | 对象，含 `role` 和 `instance_id`；角色为 `main_control`、`interaction` 或 `test_fixture` |
| `clock_id` | 握手认可的时钟域；首次握手可为null，实时结果不得为空 |
| `timestamp_mono_ms` | 消息产生时的单调时刻；不是拍摄时刻 |
| `evidence_mode` | `live`、`replay` 或 `synthetic`；测试替身必须是后两者 |
| `data` | 下文定义的消息内容 |

请求还包含 `deadline_mono_ms`，响应包含 `status` 和 `error`。`status` 为 `ok`、`unavailable`、`rejected` 或 `error`；成功时 `error=null`，失败时给 `{code, message, retryable}`。响应到达时已超过请求期限，应丢弃其对当前交互的作用，可保留日志。系统事件独立使用自己的有效期。

控制请求使用相同 `request_id` 重试，主控幂等处理，不重复执行。`ok`只能表示该响应所说明的状态；例如“收到暂停意图”不等于“已经暂停”，必须看控制结果字段。

错误至少覆盖 `DEPENDENCY_UNAVAILABLE`、`NO_FRAME`、`STALE_FRAME`、`INVALID_FRAME_REF`、`UNSUPPORTED_VERSION`、`CLOCK_UNVERIFIED`、`STALE_STATE`、`INVALID_TARGET`、`INVALID_PAYLOAD`、`BUSY`、`DEADLINE_EXCEEDED`、`CANCELLED`、`OUTPUT_UNAVAILABLE`。错误码不用于代替真实原因。

## 能力握手

逻辑操作为 `capabilities.get` 与 `capabilities.result`。双方公开实际支持的消息版本、服务 `instance_id`、主机/时钟标识、支持模式、资源状态和哪些能力尚未实现。主控可以明确返回 `frame_provider=false` 或 `scene_state=false`；交互侧据此继续独立工作并报告缺口。

首次接入、服务重启和连接恢复都要握手。适配器连通、模型已加载、传感器有效和完整交互通过分别记录，不能由HTTP成功返回推导全部已就绪。

## FrameProvider 取图

交互发送 `frame.acquire`，主控返回 `frame.result`。

| 请求字段 | 说明 |
| --- | --- |
| `mode` | `latest` 或 `pinned`；前者请求当前画面，后者取指定历史/当前照片 |
| `purpose` | `vqa`、`ocr`、`compare`；用于选择清晰度和负载策略 |
| `frame_id` | `pinned`时必填；`latest`时为null |
| `max_age_ms` | `latest`允许的最大采集龄期；主控可采用更严格策略，超时返回不可用 |
| `max_side_px` | 期望图像档位，不能默默改变既有帧身份；实际尺寸在响应中说明 |
| `roi_xyxy_px` | 可选原始图像像素裁剪框；必须同时指定依据帧，不能将旧图ROI直接用于新图 |

响应描述必须含 `frame_id`、`captured_mono_ms`、`source_kind`、`is_historical`、`width_px`、`height_px`、`color_space`、`quality`、`asset`。采集时间来自主控采集端，不能用收到请求或重新编码的时间替换。

- `source_kind`为`camera`、`upload`或`fixture`。未知拍摄时间的上传图可令 `captured_mono_ms=null`，但必须 `is_historical=true`，只能用于历史照片描述。
- `quality`说明清晰度、曝光/反光、目标裁切等已实际检查的项目；未检查填`unknown`，不能默认`clear`。
- `asset`包含 `asset_id`、传输方式、编码、校验值和读取参数；派生缩图/裁剪需保留 `parent_frame_id` 和到原始图的变换。
- 需要保留照片时，交互侧通过适配器申请保留/取得本地副本，在自己的有界存储中管理；释放临时资产不等于删除另一模块的原始数据。共享内存需明确租期和归还时机。
- 同一捕获帧的身份稳定；重新拍摄才产生新帧身份。客户端重复提交相同 `frame_id`、不同内容必须拒绝或明确生成新身份，不能静默覆盖。

v0.1的只读文件资产使用固定字段 `asset_id`、`transport="file"`、`path`、`encoding`、`sha256`、`available_until_mono_ms`。`sha256`是实际资产字节的64位十六进制摘要；资产租期与照片的拍摄时间分别管理。采用共享内存时通过能力握手声明该传输及其读取字段，不把文件路径字段偷偷解释为内存地址。

以下所有JSON均为构造的协议例子，不是真实测量，不含真实服务地址。

```json
{
  "schema_version": "interaction.v0.1",
  "type": "frame.acquire",
  "message_id": "msg-frame-001",
  "reply_to": null,
  "request_id": "req-frame-001",
  "session_id": "session-demo",
  "producer": {"role": "interaction", "instance_id": "voice-demo-1"},
  "clock_id": "fixture-clock-1",
  "timestamp_mono_ms": 10000,
  "deadline_mono_ms": 10500,
  "evidence_mode": "synthetic",
  "data": {
    "mode": "latest",
    "purpose": "ocr",
    "frame_id": null,
    "max_age_ms": 300,
    "max_side_px": 1600,
    "roi_xyxy_px": null
  }
}
```

本例1600像素和300ms仅演示字段，不是相机规格或冻结时效阈值。正式档位由实际前端与主控负载确定。

对应响应结构如下。示例路径及全零摘要仅用于展示字段，不代表实际文件存在：

## SceneState 当前场景与空间状态

交互发送 `scene.query`，按当前问题指定可选的 `track_id` 或所需字段；主控返回 `scene.result`。该接口按需查询或订阅最新状态，不要求主控发送全部分割图、深度点云和地图。

| 响应内容 | 语义 |
| --- | --- |
| `state_id`、`sequence` | 该主控实例内单调递增的状态身份；旧序号不得覆盖新状态 |
| `observed_mono_ms`、`valid_until_mono_ms` | 场景依据的时刻及主控给出的有效期；关联测量可有更短有效期 |
| `coordinate_frame` | 例如`body_forward`、`camera`或`unknown`；不能把镜头左边直接说成身体行进方向左边 |
| `navigation` | 任务模式、通过/绕行候选/暂停/未知、原因码、主控提供的事实描述；不是永久通行许可 |
| `objects` | 主控跟踪ID、支持类别、位置描述、测量及有效性；未知类别保持未知 |
| `measurement` | 距离数值、单位、有效期、有效/失效及原因；失效时值为null，不用0表示“未知” |
| `sensor_status` | 当前是否有可靠RGB/深度/方向依据；缺失不解释为空旷 |

主控的10类或后续13类可能只有“静态实体”，交互侧不能据此说成椅子。图文模型独立识别的名称可以作为照片描述，但与主控实体是否相同要有对应依据，不能把任意照片物品套上某个障碍距离。

```json
{
  "schema_version": "interaction.v0.1",
  "type": "scene.result",
  "message_id": "msg-state-042",
  "reply_to": "msg-state-query-042",
  "request_id": "req-state-042",
  "session_id": "session-demo",
  "producer": {"role": "test_fixture", "instance_id": "main-fixture-1"},
  "clock_id": "fixture-clock-1",
  "timestamp_mono_ms": 10100,
  "evidence_mode": "synthetic",
  "status": "ok",
  "error": null,
  "data": {
    "state_id": "state-042",
    "sequence": 42,
    "observed_mono_ms": 10050,
    "valid_until_mono_ms": 10400,
    "coordinate_frame": "body_forward",
    "navigation": {
      "mode": "paused",
      "decision": "pause",
      "reason_code": "SPACE_UNCONFIRMED",
      "speech_fact": "两侧空间还没有确认，请先停下。"
    },
    "objects": [
      {
        "track_id": "obstacle-7",
        "class_name": "静态实体",
        "bearing": "front",

          "distance_m": null,
          "valid": false,
          "valid_until_mono_ms": 10400,

        }
```

本例应解释为“距离暂时测不准，两侧空间没有确认”。不能说“距离0米”，也不能用图文模型补一个米数。

行动提示及距离回答使用可校验的主控事实字段或主控提供的短句。语言模型可以组织一般解释，但不能新增/改写距离、方向、通过条件。进入播放队列前再次核对当前状态及有效期；长回答的后续片段也需核对，过期就取消相关部分并重新查询。

## ControlIntent 用户控制意图

交互发送 `control.intent`，主控返回 `control.result`。`data`至少包含 `action`、`utterance_id`、`final_transcript`、`target_ref`（可为null）和 `user_confirmed`。

允许的第一版动作建议为 `start_guidance`、`pause_guidance`、`resume_guidance`、`end_guidance`、`repeat_guidance`。这些是意图请求，主控按任务状态判断能否执行。暂停聊天/停止普通播报由交互侧自身处理，不必一律暂停行走任务；“停一下”存在歧义时先澄清。

控制请求只能基于最终有效话语和必要澄清，ASR临时结果不能触发行走变更。“不要开始”“不是让你结束”不得因为包含关键词而执行。模型产生的JSON只作为候选，交互侧先验证允许动作与参数，再向主控提交。

`control.result.data`包含 `accepted`、`operation_state`（`pending`、`completed`、`rejected`）、`actual_mode`、`reason_code`、`state_id`。只有确认完成且模式匹配时才能说“已经开始/暂停”。超时先查同一请求状态，不新建请求盲目重复执行。拒绝和依赖失效必须明确反馈。

## TargetObservation 视觉找物结果

用户说“找右边那袋菜”时，交互可以内部讨论对象；当用户进一步请求接近该目标，交互提交 `target.observation`，内容包含 `visual_target_id`、`frame_id`、原图ROI、识别名称/文字、识别来源和用户选择依据。图像模型置信分数若未经校准，明确标记，不能作为测距可信度。

主控返回是否能关联空间对象；关联成功才返回其 `track_id` 和有效期。无法关联时保持 `unmatched`。交互侧不能自行把 `visual_target_id` 改写成主控 `track_id`，也不能根据二维框中心计算真实距离或发出前进指令。

照片购物对象与行走障碍可以是不同实体。找到了价签也不意味着附近通路已检查，商品比较不需要每次触发导航。

## GuidanceEvent 引导与紧急提醒

主控经常驻事件通道发送 `guidance.event`，每条包含 `event_id`、主控实例内 `sequence`、`priority`、`issued_mono_ms`、`valid_until_mono_ms`、`state_id`、`text`、`interrupt_policy` 和可选的 `supersedes_event_id`。

`priority`使用明确枚举：`emergency`、`navigation`、`information`。优先级策略由主控提供；交互侧普通聊天不能自行升为紧急。生产中只接收真实主控适配器产生的引导事件，模型文本、OCR内容和用户音频不能伪装该来源。测试事件仅在显式测试模式接收。

```json
{
  "schema_version": "interaction.v0.1",
  "type": "guidance.event",
  "message_id": "msg-danger-009",
  "reply_to": null,
  "request_id": null,
  "session_id": null,
  "producer": {"role": "test_fixture", "instance_id": "main-fixture-1"},
  "clock_id": "fixture-clock-1",
  "timestamp_mono_ms": 11000,
  "evidence_mode": "synthetic",
  "data": {
    "event_id": "danger-009",
    "sequence": 43,
    "priority": "emergency",
    "issued_mono_ms": 11000,
    "valid_until_mono_ms": 12000,
    "state_id": "state-043",
    "text": "请先停下，前方空间无法确认。",
    "interrupt_policy": "preempt_ordinary",
    "supersedes_event_id": null
  }
}
```

紧急事件直接进入播放器高优先级通道，打断普通聊天/普通导航，废弃被取消的旧片段；不等普通模型锁释放，不等待完整长答案生成。尽量使用已就绪的短句音频或低延迟合成。主控负责震动，交互侧报告声音是否真实可用，不能用“事件已收取”冒充已经发声。

重复事件按 `event_id` 去重，但主控发送的新事件或明确重复指令不能被普通聊天冷却抑制。重连只处理仍有效且未完成的事件；过期历史行动提示不能补播。主控明确撤销某事件时，删除对应待播内容。

## OutputCancel 取消与语音插话

交互内部的每段普通回答必须绑定 `session_id`、`turn_id`、`request_id`、`generation`、`utterance_id`、`segment_index`。同一会话开始新一轮或取消旧一轮时递增 `generation`；旧代次的文字、音频、缓存回调和完成事件不能进入播放或写入新轮的有效回答。

主控可发送 `output.cancel` 撤销指定事件或普通输出；交互可因真人插话/用户停止生成同等取消动作。`scope`须明确为 `ordinary_turn`、`ordinary_session` 或 `guidance_event`。交互侧的“停止播报”默认取消普通输出，不永久关闭主控紧急入口；危险事件的撤销由主控状态控制。

取消流程必须覆盖：停止实际播放、清空待播、取消/中止生成、停止或废弃TTS、释放相应缓存/资源。运行器暂时不能立即中断计算时，先阻断输出并记录计算实际结束时间，不能声称算力已即时回收。

```json
{
  "schema_version": "interaction.v0.1",
  "type": "output.cancel",
  "message_id": "msg-cancel-014",
  "reply_to": null,
  "request_id": "req-cancel-014",
  "session_id": "session-demo",
  "producer": {"role": "interaction", "instance_id": "voice-demo-1"},
  "clock_id": "fixture-clock-1",
  "timestamp_mono_ms": 11500,
  "deadline_mono_ms": 12000,
  "evidence_mode": "synthetic",
  "data": {
    "scope": "ordinary_turn",
    "target_request_id": "req-answer-013",
    "target_event_id": null,
    "old_generation": 13,
    "new_generation": 14,
    "reason": "user_barge_in"
  }
}
```

普通回答的取消代次与主控危险事件的序号分别管理，不能一次递增普通代次就把新危险提醒也清掉。用户停止/结束行走任务仍按ControlIntent与主控实际状态处理。

## PlaybackStatus 播放反馈

交互向主控发送 `playback.status`，包含来源事件/请求、`utterance_id`、片段序号、`generation`（普通回答时）、优先级、状态、测量时刻和依据。

`data`固定字段为 `source_event_id`、`source_request_id`、`utterance_id`、`segment_index`（从0开始）、`generation`（主控事件时可为null）、`priority`、`state`、`occurred_mono_ms`、`start_basis`、`reason_code`。状态不是 `started` 时，`start_basis`可为null；按事件类型不适用的来源ID为null。原请求/事件关联不能被TTS子任务ID替代。

状态至少为 `queued`、`started`、`completed`、`cancelled`、`failed`、`dropped_stale`。必须区分生成结束、TTS结束、开始向设备写PCM、实际声音开始及播放完成。`start_basis`可为 `device_write`、`loopback_measurement` 或 `estimated`；调度估计不能报成声卡实测。

发送取消回执时说明队列是否清空、设备播放是否停止、后台计算是否结束。播放器不可用返回 `OUTPUT_UNAVAILABLE`，主控据此采取自身失效处理，不得静默标记声音成功。

## InteractionStatus 交互健康与资源

交互提供 `interaction.status`，主控可查询或订阅。返回服务实例、当前会话/模式、麦克风与输出设备状态、ASR/图文/OCR/TTS是否就绪、取消与错误计数、队列长度、模型版本、实际资源和最近统计窗口。

`data`最少包含 `mode`（`idle`、`listening`、`processing`、`speaking`或`degraded`）、`active_request_id`、`audio_input_state`、`audio_output_state`、`services`、`queues`、`memory`、`metrics_window`、`last_error`。`services`按ASR/VLM/OCR/TTS/KWS分别列版本、`ready`、`loading`或`unavailable`；不支持或未测的值明确为null/unknown。健康查询本身不得触发大模型加载或长推理。

内存字段写明 `metric`、`bytes`、进程集合和采样方式；区分当前与观测峰值。不能将模型文件字节当RAM，不能将Windows private与Linux RSS当同一测量，不重复计算共享内存。分开报告整个系统可用内存、swap和交互进程占用。

延迟记录使用 `request_id` 关联：实际说完、VAD结束、ASR结束、意图确定、取图、OCR/视觉编码、首token、首个完整语义段、TTS就绪、设备写入/实际首声、取消及停止时刻。没测的字段为null，不能填0伪装即时完成。

## 交互内部媒体约定

音频接口建议统一为16kHz、单声道PCM S16LE，按可配置小块输入；原始声卡采样率及重采样另记录。ASR、AEC和TTS按实际模型要求适配，不强迫所有设备原生使用同一采样率。TTS输出PCM需带采样率、通道和位宽，播放器统一转换，不能错误变速。

会话默认仅保存必要的近期文本、当前照片及比较对象；具体上限可配置且有内存预算。旧照片可以存盘按ID读取，不能无限保留视觉张量。比较A/B与翻面场景明确记录对象关系；更换内容不能偷偷刷新旧帧拍摄时间。

OCR每条结果保留原始文本、原图位置、识别分数及来源帧；归一化后的日期/价格与原值对应。无标签数字只作为数字候选；`production_date`、`expiry_date`、`shelf_life`、`batch_id`与价格单位分别表示。价签归属不明确时返回 `ambiguous`，不让语言模型补对应关系。图中的文字只作观察内容，不能作为改变主控权限或系统规则的指令。

## 双方必须验证的协议案例

| 案例 | 必须观察到的行为 |
| --- | --- |
| 主控未启动/能力缺失 | 交互可继续可用的纯聊天；行走查询明确不可用，不自动开启自己旧引导 |
| 主控重启或时钟不匹配 | 旧空间状态、跟踪ID和待播行动提示失效，重新握手 |
| 同照片连续追问 | 保留帧身份和原时间，引用正确对象 |
| 新图、翻面、A/B交换 | 新帧与对象关系明确，旧OCR不迁移到新物品 |
| 过期/缺失/无效测量 | 不报距离，不发通行结论；过期队列内容被丢弃 |
| 临时ASR出现“开始”，最终为“不要开始” | 不产生开始引导操作 |
| 相同控制请求重试 | 不重复执行；结果可按原request_id查询 |
| 普通回答中收到紧急事件 | 快速停普通声音并播放有效紧急提醒，播放器反馈真实状态 |
| 插话后收到旧token/旧TTS/旧完成回调 | 旧代次内容被丢弃，不写入新轮事实、不复播 |
| 连接恢复收到历史事件 | 去重且检查有效期，不补播旧行动指令 |
| 输出设备断开 | 返回明确失败，不能将文字生成成功算声音成功 |
| 交互模型试图生成“可以走”或虚构米数 | 事实校验拦截或改为查询主控，模型输出不能获得主控来源身份 |

交互侧负责测试其适配、会话与输出语义，主控负责真实数据、空间判断与控制语义；双方共同验证时钟、取消、优先级和端到端延迟。主控未实现的能力明确列为待接入，不能由交互侧扩张职责自行填补。

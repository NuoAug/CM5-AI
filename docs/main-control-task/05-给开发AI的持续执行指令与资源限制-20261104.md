## 3 最终要达到的使用体验

全部能力在随身计算盒本地运行。最终产品是眼镜加随身计算盒，电池在盒内；电脑用于开发、测试和观察。新闻功能取消，不增加云端兜底。

| 能力 | 需要形成的实际表现 |
| --- | --- |
| 自然聊天 | 能理解前文、停顿、补充和纠正；“今天有点烦”之后问“为什么”“那你觉得呢”，仍能沿当前话题交流。根据语境简短回应或详细解释，适时追问，不一律输出模板建议 |
| 视觉多轮 | 按需取得当前画面，同图可以连续讨论；翻面或重新查看时更新画面；“不是左边，是右边那个”能更新对象，歧义不明时简短澄清 |
| 购物与读字 | 当前视野内找物、读标牌、包装日期、价格与单位；对应正确商品，区分生产日期、到期日、保质期和批次号。两物比较保留各自来源 |
| 及时响应 | 说话期间就处理音频，完整首段意思形成后开始说，后续继续生成和播放。首token或“正在分析”不能替代有效首声 |
| 真人插话 | 用户在设备讲话时插话，及时停声、清理待播内容并处理新话语；旧文字、音频和回调不能复活旧回答 |
| 主控协作 | 距离、通行、绕行和危险结论读取主控有效结果；紧急事件能抢占普通交流；过期、失联和重启时正确撤销旧状态 |
| 诚实处理失败 | 看不清、目标没入镜、文字歧义或关键数据缺失时明确说明，并在合适时指导用户调整，不补造数字、物体或通行结论 |

“回答详细”要求信息充分、能够继续深入，不要求每句话长篇生成。自然交流不能被降为固定命令表，目标功能不能因为资源紧张而被静默删除。半双工关闭识别或按钮取消可以用于阶段测试，但不能算真人插话目标完成。

## 4 当前平台定位

主控当前优先核查 **Orin NX 16GB完整套件**，具体载板、系统和购买尚未冻结。CM5继续用于测试和对照，不要求所有能力都必须在CM5 4GB上流畅，也不把更换主控平台当成你可以自行决定的采购。

16GB是整机资源，由系统、CPU/GPU任务、感知、深度、定位、地图、空间检查和交互共同使用。**交互侧不得按整机总容量自由扩大模型。**内存增加也不保证算力、带宽、散热和续航有同等余量。

保留真实CM5失败作为依据；已证明不合适的路径应定位关键瓶颈，再决定是否继续优化或转向目标平台。不能只因仓库名字含CM5就把最终方案锁在CM5，也不能把电脑或CM5成绩外推到NX。

## 5 必须遵守的资源额度

以下额度已由主控在本轮讨论中确认，用于当前设计和首轮目标板接入。它们是资源分配与验收约束，不是全部功能已经能够达成的性能承诺。

| 项目 | 要求 |
| --- | --- |
| 正常运行占用目标 | 整个交互子系统争取保持在 **1.5—2GiB左右**，包含持续会话与普通视觉任务的资源，不以最低空闲值代替 |
| 首轮目标板峰值接入上限 | **3GiB，即3×1024³字节**；覆盖加载、推理、任务切换和取消重试，不能忽略短时峰值 |
| 统计范围 | 图文语言部分、视觉组件、ASR、OCR、TTS、唤醒、服务、运行器、相关子进程、上下文、图像、音频、推理工作区及相关CPU/GPU分配 |
| 整机关系 | 未分给交互侧的资源由主控统筹。整机最重正常场景仍按主方案争取保留充分余量，不能由交互侧占用后要求主控让步 |
| 超出额度 | 该版本不能按当前资源预算验收；先优化并提交实际差距和替代方案，只有主控明确调整后才能采用更高接入额度 |

3GiB不是鼓励用满。不要把1.5—2GiB目标改写成“只要小于3GiB就不用再优化”，也不要把16GB减去3GiB后直接称为主控可用内存，系统和其他开销仍需核算。

主方案的整机内存余量目标为最重正常场景占用初步控制在实际可用总内存的50%—60%以内，包含系统和所有任务。这属于主控负责的联合预算，不能用它给交互侧重新计算一个更大的额度。

### 测量必须覆盖完整生命周期

至少测：冷启动加载、首次问题、持续聊天、新图、同图追问、两图比较、高清OCR、TTS与下一段生成衔接、取消后立即重试、会话达到配置上限，以及持续运行后的状态。

列明参与统计的进程和组件、精度、输入、上下文上限、采样间隔及测量方式。结合进程组PSS、运行器/GPU分配和整机状态核对；共享页或同一CPU/GPU共享分配不能重复相加，驱动侧未被进程统计覆盖的分配也不能漏报。Windows private、Linux RSS/PSS、整机占用和模型文件字节分别标注，不能混用。

同时报告系统可用内存、swap变化及可取得的峰值记录。周期采样得到的是观测峰值，应说明可能漏掉短时峰值；不能拿低频截图证明绝对峰值不过限。当前测量方法无法核清全部占用时，先标明证据缺口。

本额度约束最终部署运行，不要求GPU训练设备也只有3GiB。训练、格式转换或离线构建的资源另行记录。目标板尚不可用时可开展电脑对照，但不能声称目标板额度已通过。

### 运行时也要受控

- 对图片、音频、上下文、待处理请求及待播内容设置明确上限，长时间交流不得无限增长。
- 普通聊天不做无关视觉推理；正式版本不同时常驻多套图文候选作投票。
- 默认按单用户设计，重推理任务不无界并发。两图比较可以是一次受控任务，不能因此任意累积历史视觉张量。
- 新一轮取消旧任务时，既保护输出代次，也观察后台计算实际退出。旧任务未退出时不得持续启动新任务堆积资源。
- 不依靠持续swap或zram把明显超预算的常驻工作集包装成达标；发生换出、压缩或明显抖动时如实记录。
- 会话期间可以保持必要模块就绪，结束后按策略释放；不得为降低空闲数字而让每一轮都反复加载、严重损害响应。
- 资源阈值用于主动控制任务和报告状态，不以突然杀掉唯一播放器或紧急提示通道作为正常超限策略。

## 6 并行运行必须保护行走核心

即使交互侧低于3GiB，如果导致主控感知、空间更新或危险提醒不达要求，该版本仍不能联合验收。

线程数、运行器、图像档位、量化、缓存和调度由你选择，但不得长期无节制占满CPU/GPU换取自己的速度。普通推理、合成和网络/本地通信锁不能阻塞紧急事件入口。取消播放与关键短句输出应保持及时，主控负责独立震动。

未经主控决定，不得关闭必要环境监测、降低主控更新频率或延长空间有效期来让交互通过。停下问答是可评估的整机降级方式，仍需保持必要环境监测，不能由你自行改成“问答时暂停全部感知”。

联合测试至少包含：

1. 交互独立运行，记录质量、延迟和峰值。
2. 主控独立运行基线，由主控提供或共同测量。
3. 两侧同时运行，比较主控更新频率、P95延迟、过期结果、危险提示与交互首声、音频连续性、内存和热状态。

主控截止时间与负载以实际接口和联合测试设置为准，不用未经测量的CPU/GPU占用百分比代替。目标板缺失时完成可运行预检、明确预计部署路径，并继续独立部分，不能伪造联合通过。

## 7 自主执行空间和变更边界

你可以在自己的交互工程内自主安排工作、重构、修复、选择运行器与参数、取得许可适合的依赖、开展少量模型对照和必要训练。常规实现和回归无需逐项等待主控确认。

主控此前给出的模型及实验建议是起点，不要求永远保留某个模型。你可以提出并验证更合适的方案，但应给同题质量、速度和资源证据。先完成可运行基线，再针对真实失败决定是否微调。软件路由、图片绑定、回声和取消错误应先修工程，微调不是主要的降内存办法。

以下变化须交回主控决定：提高资源额度、加入联网依赖、删减产品能力、改变接口业务语义、扩张到其他人的职责，以及涉及新增硬件和费用的决定。

预算内无法达到目标时，提交四项信息：实际资源主要消耗在哪里；预算内能达到什么体验；替代方案增加多少资源及测出的收益；对主控并行和整机热/续航的影响。报告真实失败并不等于停止开发，应继续可独立完成的优化。

## 8 保留有效成果并清理越界工作

复用已经验证的语音、OCR、播放、日志和图片管理基础，不要求无理由重做。确认当前交付版本中已删除独立SegFormer引导及二维通道判断；如仍有独立导航、深度/空间/体型算法、新闻或云端兜底，按引用关系清理其专属实现、路由、配置和依赖。

保留语音控制引导、查询主控状态、接收危险事件及播放抢占，但它们都通过主控接口实现。正式采集使用统一FrameProvider；单独硬件测试可以使用显式的测试适配器，主控失联时不能偷偷切换并宣称已经接入整机。

修改和删除限定在自己的工程，先保留可追溯版本，核对真实路径与文件所有权。已经清理并验证的部分不重复删除。公共会话、协议、音频与播放逻辑优先共用，模型和平台差异通过适配或配置隔离，避免三套源码长期各自修复。

## 10 接口与验证原则

继续执行 `interaction.v0.1`，核对取图、场景、控制意图、目标观测、引导事件、取消、播放回执和健康状态。接口合同不等于真实主控服务已经部署，不猜地址、不构造现场测量。

主控缺失时使用明确标记的synthetic/replay替身开发，不自行写另一套导航充当主控。保持请求/会话身份、主控实例、时钟、采集时间、状态有效期和取消代次。主控重启或状态过期后撤销相关行动信息；历史照片可以继续讨论，但不能作为当前通行依据。

先修关键行为，再扩大模型和真人场景测试。至少形成三条完整可体验过程：自然多轮聊天；包装翻面读日期并追问；两商品与价格/文字比较。另测真人插话、紧急抢占、没有画面、模型超时、主控失联和音频设备失效。

用户实际说完、VAD结束、ASR结束、首个完整语义段、TTS就绪、设备写PCM和实际首声分别计时；插话开始、检测确认、实际停声和后台计算退出分别记录。不能把HTTP返回、入队或声音调度估计当成物理首声。

冷/热、单图/同图、电脑/目标板、回放/实时分别报告；没有原始依据的字段标未测。先用代表性短测定位问题，再做至少30分钟持续检查；至少2小时的整机电池与腰间散热由主控组织联合验收，记录问答使用占比。

资源上限3GiB是本轮明确的接入约束；此前首声秒数属于初始优化目标，应结合测试条件评估，不得自行声称是已达成指标。未过项目必须保留原因与证据，不能靠删除困难问题、缩短到无用回答或预置场景台词通过。

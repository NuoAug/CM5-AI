## 产品目标与完成边界

最终形态是可佩戴眼镜与腰间计算盒，电池在盒内。推理、会话、OCR、识别、语音合成和播放全部本地运行，电脑只作开发、测试与观察。当前已有CM5 4GB/32GB eMMC、Camera Module 3 Wide、ReSpeaker XVF3800和扬声器，可作为测试候选；最终计算平台尚未冻结。

整机连续佩戴目标约1—2小时；续航基准为持续行走感知与指引、期间偶尔问答，至少2小时并留余量。交互侧报告自身资源与功耗影响，主控负责整机合并核算。不能把短时电脑测试外推为盒端实时、佩戴或续航通过。

| 功能 | 需要做到的行为 | 不合格表现 |
| --- | --- | --- |
| 日常交流 | 能接住烦恼、疑问和心理学/哲学等话题；理解上下文，适时追问、表达观点、承认不知道 | 每次都像初次聊天；一律输出模板建议；编造依据；只会固定命令 |
| 视觉交流 | 按需取得当前画面，描述常见物品与环境，比较两个对象 | 每句话都重新抓拍而混淆对象；没看清也肯定回答 |
| 多轮纠正 | 理解“它”“刚才那个”“不是左边，是右边那个”“现在呢” | 忽略纠正；把商品A的文字或价格归到商品B |
| 包装与标牌 | 读取可确认文字，区分生产日期、到期日、保质期和批次号 | 凭常识补数字；把无标签的一串数字直接称为生产日期 |
| 购物找物与读价 | 在当前视野内找商品/蔬菜，关联价签、单位和条件 | 只读到一个价格就绑定商品；漏掉每斤/公斤/盒、会员或促销条件 |
| 流式语音 | 说话期间接收处理音频，完整首段意思形成后开始说，后续持续生成播放 | 等整段录音、全文和整份音频都完成才播放 |
| 语音插话 | 播报中识别真人插话，停声、清队列、取消旧生成，接新内容 | 播报期间直接关闭麦克风；只停网页声音，旧结果又回来 |
| 行走查询 | 读取主控当前有效结果，准确表达原因和必要细节 | 让图文模型凭照片猜距离、通道宽度或安全通行结论 |

“回复详细”是信息足够、能说明相关事实并继续深入；不要求每次长篇输出。先回答核心问题，再随语境展开。清晰的首句也必须有实际内容，“正在分析”不计有效回答。

不开发新闻、新闻库、模拟新闻播报或云端兜底。视野内找物不自动扩展为商场地图、全商场找菜导航或陌生楼宇定位。讨论心理话题时可以倾听和提供一般知识，不凭几句话给用户下诊断，也不伪造出处。

## 主控给出的重构建议

建议分成七个内部模块，名称可以调整，职责保持清楚：

| 模块 | 工作内容 |
| --- | --- |
| AudioInput | 常开采集、音频格式转换、AEC参考接入、VAD、唤醒和真人插话候选 |
| ASR | 流式识别、临时结果与最终结果区分、否定/改口保留 |
| DialogueManager | 会话、指代、图片和对象关联、问题路由、请求取消代次 |
| VisionAndOCR | 按需图文推理、高清局部OCR、商品/价签/日期字段关联 |
| ModelRunner | 单一小图文模型的文字与视觉调用、运行器/缓存/量化、真实取消能力 |
| SpeechOutput | TTS、完整语义分段、连续播放、优先级、旧片段丢弃与播放反馈 |
| MainControlAdapter | 配套合同的唯一接入口，管理时间/版本/失效/重连；开发替身与正式适配器可替换 |

Flask或其他网页服务只做调试入口，不让浏览器承担必须常驻的会话、收音、播放或引导状态。最终断开电脑、关闭调试页面，盒内核心交互仍能工作。

主处理顺序：音频块进入ASR；最终用户话语进入会话管理；普通聊天调用文字路径；看图问题调用FrameProvider与VQA；数字/日期/价格优先OCR及字段校验；行走问题读取SceneState；有效回答分段交TTS播放。紧急事件走独立高优先级入口，不能排在普通推理锁后面。

纯聊天不做图像编码。日常聊天和VQA优先共享一个图文模型，避免重复常驻语言模型。正式感知继续由主控提供，不在交互侧复制一份感知网络。

## 主控建议的模型选择方法

先建立原版本的真实基线，再比较少量有目的的候选。每类先保留一个基线和一个改进候选，正式版本只保留实际采用的运行路径。只有明确失败证明需要，才扩大候选范围。下列是建议，不是已经通过的型号或硬件承诺。

| 类别 | 建议起点 | 对照与选择依据 |
| --- | --- | --- |
| 图文与聊天 | 现有MiniCPM-V 4.7 1B作为质量/兼容基线 | 优先比较Qwen3.5-0.8B量化图文版本；同题测中文自然度、纠正、多轮、两图比较、数字事实、内存和延迟 |
| ASR | 现有Paraformer-zh-small INT8作为离线整句基线 | 对照sherpa-onnx流式Paraformer中英版本；最终要求真实增量处理，不能把切碎录音反复整句识别直接称为原生流式 |
| TTS | 现有Piper作为速度与播放连续性基线 | 中文huayan音色数据许可未闭合；对照许可明确的MeloTTS中文ONNX等候选，验证数字/字母/单位、合成速度、内存与声音清晰度 |
| OCR | 现有RapidOCR及实际PP-OCR模型 | 先核实实际权重/版本与字段质量，调整图像质量、局部裁剪、模型档位；不把所有OCR任务交给VLM自由生成 |
| 唤醒/VAD/AEC | 现有KWS与音频基础 | 用真人和真实扬声器回声标定；阈值变化记录误唤醒、漏唤醒、误打断与漏打断 |

2026年11月2日核查的文件量级：MiniCPM语言Q4_K_M与视觉F16约1.78GB；Unsloth转换的Qwen3.5-0.8B语言Q4_K_M约533MB、视觉F16约205MB，合计约738MB。后者是转换方发布的制品，不是Qwen原厂GGUF。上述均为存储大小，不能推导运行峰值或速度。要记录实际下载版本及每个组件摘要。[MiniCPM文件](https://huggingface.co/openbmb/MiniCPM-V-4.7-1B-gguf/tree/main)、[Qwen原始模型](https://huggingface.co/Qwen/Qwen3.5-0.8B)、[Qwen转换制品](https://huggingface.co/unsloth/Qwen3.5-0.8B-GGUF/tree/main)。

Qwen的小尺寸版本原厂定位包含原型和专用微调用途，不能先假定它足以承担全部自然交流。中文质量不合格时，应说明具体失败、量化前后差异和更大模型对照的收益，不为省内存强行宣布通过。CM5、RK3588、Jetson上的同名模型也不能直接互换性能结论。

本地部署必须核查视觉编码器/投影文件、语言权重、词表、模板、停止符、预处理与运行器是否配套。GGUF不能直接冒充RKNN/RKLLM的NPU部署；支持文字模型不等于完整视觉路径可用。新模型先完成目标系统的最小加载、单图和纯文字推理，再投入微调。

许可要分别核代码、权重、音色/词典、训练数据及转换制品。记录可用于当前研发与最终交付的条件；“运行器开源”不代表其全部模型可任意使用。Piper音色、ASR权重等来源若不明确，先解决或替换，不能用仓库根部许可证覆盖全部依赖。[Piper音色说明](https://huggingface.co/rhasspy/piper-voices/blob/main/zh/zh_CN/huayan/medium/MODEL_CARD)、[流式ASR路径](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-paraformer/index.html)、[MeloTTS许可](https://huggingface.co/myshell-ai/MeloTTS-Chinese)、[Melo ONNX路径](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html)。

## 如何优化

| 优先项 | 操作建议 | 必须观察的副作用 |
| --- | --- | --- |
| 去掉重复工作 | 删除越界引导；聊天不看图；同图复用可验证的视觉缓存；OCR只处理相关区域 | 缓存不能跨图片/模型/裁剪错误复用；裁剪不能漏掉字段标题或单位 |
| 提前处理语音 | 流式ASR，区分临时与最终转写；有语音活动时及时处理，不等待长文件上传 | 正常停顿不误结束；“不要”“不是左边”不能在增量阶段丢失或先执行 |
| 缩短首声 | 生成完整首段意思后开始TTS，下一段生成与播放衔接；会话期间保持必要模块就绪 | 不先播半个否定句/数字；详细答案质量和连贯性不能为低延迟让步 |
| 做到真实打断 | AEC＋真人语音检测，取消模型请求、TTS、队列和播放器；所有片段检查请求代次 | 静音后不复播旧内容；回声/旁人声音不频繁打断；取消回收不阻塞紧急声道 |
| 控制内存 | 有界音频环形缓冲、图片数、上下文和生成长度；减少图像复制；必要时用轻量本地运行器替代完整训练框架 | 不无限保留全部照片/聊天张量；不能靠swap掩盖持续超预算；不把释放Python变量等同于已释放底层内存 |
| 控制计算争用 | 测1/2/4线程、批大小和图像token档位；按主控工作模式调节普通问答资源 | 线程更多不一定更快；检查感知与定位被挤占、音频欠载和热降频 |
| 缓存与常驻 | 同一会话避免反复加载；结束后可按资源策略释放；固定真实提示可缓存音频 | 冷启动单列；缓存的是表达，不得把旧场景判断当新事实 |

每次优化先定位瓶颈，只改变一个主要因素，使用同一组输入对照正确性、首声、总时间和峰值。若只是网页先显示字、缩短回答或删掉困难问题，不能宣称模型推理或交互体验已经改善。

视觉低分辨率适合粗看场景，小字要保留高分辨率原图并按需裁剪。图像像素降低不一定减少运行器的视觉token，要记录实际token和编码耗时。两图比较保留A/B身份，不要把重新编码后的图片编号覆盖成同一个。

AEC先用现有XVF3800验证真实播放参考与采集通道。最终换小型音频前端时重新测，不能沿用台架AEC成绩。按钮取消可用于先打通控制链，但正式语音插话验收必须使用真人声音。[XVF3800原厂能力](https://wiki.seeedstudio.com/respeaker_xvf3800_introduction/)。

## 如何开展项目专用训练

先用预训练模型跑基线，按真实失败归类。能通过接口、OCR字段逻辑、图片关联或音频处理解决的问题，先修工程原因；不要把全部错误交给微调。

训练由你在自己的合适训练设备上完成，盒端主要做推理。数据至少覆盖：自然接话与长短调整、口语省略/否定/改口、同图追问、翻面换图、两商品比较、文字不清、价签对应、无法确认时澄清，以及读取主控结果时不改变事实。图文训练使用照片与对话答案，不直接拿主控像素标签当聊天训练集。

训练、验证、最终测试按拍摄批次/商品/场景/对话来源划分；同物品近似照片或同一对话改写不能随机散到各组造成泄漏。合成数据可辅助，但真人语音、实际照片和独立测试必须保留。生成训练答案要人工复核，记录数据来源与许可。

优先尝试有限的监督微调或LoRA等适配方式，冻结实验设置，保留基线和失败样例。按事先确定的独立测试比较“未微调/微调后、较高精度/部署量化”的质量与资源；不能事后只选好看的轮次。微调不会自动增加看不清的图像信息，也不能保证小模型获得更大模型的知识和推理能力。

## 主控建议的实验顺序

| 阶段 | 执行内容 | 阶段产物与退出条件 |
| --- | --- | --- |
| M0 清理和基线 | 盘点现版本，删除越界实现，确认实际模型/依赖；固定一组测试输入，测原交互基线 | 作用域清楚、旧版本可追溯、清理后能启动；不再依赖本地独立引导 |
| M1 语音闭环与接口 | 用本地主控替身开发合同；流式识别、TTS连续播放、取消和危险抢占；真实音频设备独立测试 | 正常/否定/改口/失效路径有记录，替身明确标记；旧音频不会复活 |
| M2 图片和会话 | 同图、换图、翻面、对象纠正、两物比较；绑定帧号、时间、OCR与对象 | 能解释每轮用了哪张图；历史照片和当前空间不混用 |
| M3 模型对照 | 同一组输入比较现有图文模型与较小候选，包含纯聊/单图/多轮/两图 | 给出选择及失败边界；目标板至少完成可运行预检，不能只有电脑截图 |
| M4 数字与体验 | 包装日期、价格/单位/商品对应、模糊反光；真人自然聊天与插话 | 不猜关键数字，能帮助调整；语音体验有人工评价与原始记录 |
| M5 必要微调与联合验收 | 仅针对确有收益空间的失败训练；接入真实主控，做热稳态、资源和失效联合测试 | 交付完整离线包、复现命令与分项状态；所有未测/未过项目明确列出 |

接口工作不等正式训练完成；主控服务或目标板暂时不可用时，用开发替身与真实素材回放继续独立部分，同时准确列出缺失输入。不能用替身通过替代真实主控/硬件验收。11月20日前优先交付真实可运行闭环，不能到最后只交模型名称或方案。

## 验收与证据要求

首轮测试集建议至少包含30条真人语音（含否定、改口、停顿和噪声），20组多轮会话（其中至少10组真实视觉序列），10组价格/日期/商品对应案例，以及20次真人插话/回声/紧急事件组合。它们用于开发门槛，不是泛化能力证明；正式结论再扩展独立素材。

必须覆盖：没有主控、没有画面、同图追问、相机换对象、翻面“现在呢”、模糊数字、多价签、过期空间、主控重启、取消后晚到片段、播报时插话、设备自己的回声、模型超时、音频设备断开、低内存和服务重连。有限案例中发现串图、猜关键数字、过期行走放行或取消后复播，先修复，不能用平均分掩盖。

| 测量项 | 首轮工程目标 | 报告规则 |
| --- | --- | --- |
| 普通聊天首段有效语音 | 热启动P95争取≤2秒 | 从用户实际说完计时，区分VAD判断结束；首字/等待提示不计有效首声 |
| 同图追问 | P95争取≤3秒 | 固定是否命中视觉缓存，不能混报 |
| 新图/清晰文字 | P95争取≤4秒 | 取图、编码、OCR、生成和播放分别记录；重拍次数另外统计 |
| 插话后停声 | 确认有效插话后争取≤200ms | 另报从真人开始插话到检测的时间；检测耗时不能从体验总延迟里消失 |
| 基础交互常驻内存 | 不含图文模型，先争取约400—600MiB | 包含收音、ASR、TTS、会话、运行器与服务；计量方式明确 |
| 整个交互侧峰值 | 含图文/OCR/缓存，先争取约1.5—2GiB | 不是整机预算；主控还需叠加感知、深度、定位、系统和余量 |

上述数值是主控提供的初始优化目标，尚未冻结为全部平台承诺。必须实测并报告差距；达不到时说明瓶颈与建议，不擅自降低功能或伪称已通过。每个关键热路径先取得不少于30次有效样本，报告P50/P95、失败数和样本数；小样本不宣传稳定P99。

同时测首次启动、首次问题、连续会话、切换图片和热稳态。分开记录进程RSS/PSS（可得时）、系统可用内存、swap、CPU、温度、频率/降频与音频欠载；GPU/NPU共享内存避免重复相加。先做约30分钟稳定性检查，再由主控组织至少2小时整机电池与实际腰间散热验证，并记录问答使用占比。

最终断网测试应阻断对外网络，保留必要的本机通信，验证冷启动、模型/词典/音色加载与全流程无需下载或远端接口。研发阶段可以联网取得许可适合的依赖；最终运行不得依赖网络。

## 交付清单

1. 当前可运行源码与确定版本；清理说明、配置项、启动/停止/卸载步骤。配置使用实际目标平台，不能要求主控猜测隐藏环境变量。
2. 离线运行包：模型及所有视觉/音频组件、词表、音色、OCR资源、运行器或准确的离线安装材料；附逐文件大小、SHA256、来源、许可和依赖版本。仓库不便容纳大文件时另提供可核验的模型包。
3. 配套合同适配器、明确标记的主控替身、有效和无效协议样例、接口回归方法。传输实现及正式接入参数写清楚。
4. 至少三条可复现完整演示：自然多轮聊天；包装翻面读日期并追问；两商品与价签比较。另有真人插话、危险抢占和主控失联演示。
5. 测试报告与必要原始结果：输入、版本、设置、实际回答、错误、分段耗时、内存、温度、取消与恢复。分清电脑/目标板、回放/实时、候选/默认。
6. 最终给主控一页结果：采用什么模型/精度/运行器，哪些已过、未过和未测，目标板需求及联合运行风险。保留具体待补项，不以“已支持”代替真实运行证据。

完成范围是离线交互子系统及其适配；整机能否持续安全地提供行走辅助，由主控根据联合验证判断。代码与结果按配套GitHub流程提交PR给主控审查，不以直接更新main替代审查。超出本任务的产品能力、跨模块语义变更、采购与额外外部沟通仍归主控协调，不自行向其他聊天或人员派发任务，不建立接力或交接记录。

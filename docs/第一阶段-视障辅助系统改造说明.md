# 第一阶段改造说明（v1.2.0）

本阶段把现有测试台从“浏览器轮询的单帧引导”改成“服务端持续引导 + 结构化意图 + 统一输出仲裁 + 可选设备语音”，并在不更换现有模型的前提下修正了日志里暴露的几类问题。

## 结论先行

- 已完成：引导感知改为服务端持续循环、最新帧覆盖、时效/看门狗、连通通道与状态机、危险抢占播报、意图控制动作、KWS 接入、帧标识冲突检测、VLM 计时字段修正、部署脚本与回归工具。
- 已实测：Windows 开发机 153 项单元测试通过；AI 示例图回放 12/12 通过；引导单帧 P50 约 123–129 ms。
- 未实测：CM5 真机的 Picamera2、ALSA、线程/内存/温度、8 小时组合压力；真机「小冰小冰」唤醒率与误唤醒率；真实盲道/障碍数据。
- 不要把 Windows 的数字当作 CM5 性能；也不要把“识别到地面”当作“已经证明可以安全通行”。

## 两条处理链

```text
持续引导（设备端）
CSI 摄像头（或浏览器调试帧）
  → 最新帧槽（只保留 1 帧）
  → 图像质量 + 分割置信度/熵
  → 近处种子 + 连通通道 + 分层瓶颈
  → 前方物体证据 + 危险类别
  → 状态机（stop / straight / left / right / unavailable）
  → 输出仲裁（危险 priority 0 抢占）
  → 短语音 / 浏览器 SSE / 可选 ALSA

语音交互
麦克风 → KWS（小冰小冰）→ VAD → ASR → 规则意图
  → 控制动作（引导/播报/摄像头）或视觉任务
  → VLM/OCR → 安全一致性守卫
  → 输出仲裁 → TTS → 播放
```

引导循环不依赖浏览器页面帧率；浏览器只负责送帧和显示（Windows 调试），CM5 由 Picamera2 直接送帧。

## 引导算法（本阶段实际实现）

1. 输入 384×288，SegFormer-B0 输出类别图与 softmax 概率。
2. 质量门：平均亮度、过曝/欠曝比例、对比度、拉普拉斯方差；不通过直接 `unavailable/low_quality`。
3. 可走候选：`floor/sidewalk/rug/path` 且置信度 ≥ 0.55、熵 ≤ 0.55；低置信区域一律不算可走。
4. 近处种子：画面最底部 12% 中连续可走地面的最大横向宽度，低于阈值返回 `no_seed`，不强行选左右。
5. 从种子做 4 邻域连通，只保留与脚下相连的可走像素。
6. 分三层（近 0.78–1.0、中 0.62–0.80、远 0.48–0.62）在左/中/右通道计算连通占比与逐行最大连续宽度；宽度先减去边界余量，再检查瓶颈，不用平均面积。
7. 前方物体证据：在 y 0.40–0.85 的左/中/右通道统计自行车、垃圾桶、桌椅、货架、门、标牌等类别占比；中间 ≥18% 或两侧 ≥10% 时不允许把该通道当作可走。
8. 危险优先：楼梯/扶梯/台阶 ≥2%、人 ≥8%、道路 ≥15%（占危险 ROI）立即 stop；危险类别来自 150 类 ADE20K。
9. 只有近、中层的占比和瓶颈都合格，并且远层仍有一定连通时，才给出直行；否则先看左右是否有合格通道，没有就 stop。左右都合格但差距小于 5% 且瓶颈差小于 2 px 时也 stop，避免在模糊边界上左右摇摆。
10. 像素宽度未做几何标定，输出 `width_unit=pixel`、`calibrated=false`，不换算厘米。

状态机：

- 危险/无法通行立即 `stop`，不等待方向防抖。
- 危险 `stop` 保持 1.5 s；恢复需要连续 4 帧以上且至少 0.8 s 的合格证据。
- 左右切换需要 3 帧；已有方向切换还要满足 0.6 s 最小间隔。
- 方向与原因分开；`raw_direction/raw_reason` 保留单帧判断，`state/reason` 是稳定输出。
- 帧过期 0.6 s、推理看门狗 2.5 s；超时输出 `unavailable/stale` 或 `model_stuck`，撤销旧直行指令。
- 进程内超时全部用 `time.monotonic()`；墙钟只用于日志。

## 语音与意图

- KWS 使用 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01`，关键词文件为拼音 token。模型卡标注 Apache-2.0。
- 关键词文件：`app/config/keywords.txt`，当前包含「小冰小冰」「小冰」。
- 浏览器调试保留 KWS-first：先 KWS，命中才送 ASR；KWS 未就绪时退回 ASR 文本匹配。设备端由 `device_voice.py` 常开。
- 唤醒后播放「我在，请说」，服务端维护 15 秒免唤醒窗口。
- 否定优先：`不要停止引导`、`别停` 不执行停止。
- `停止播报` 只取消输出队列，**不关闭引导**；`关闭引导` 才停止引导。
- `停一下` 结合状态：仅引导→停引导；仅播报→停播报；两者同时→澄清。
- 低置信/短文本→`unknown`，只回“没听清”，不调用 VLM。
- 视觉追问必须有当前且未过期的画面；没有画面直接返回固定提示。
- 引导提示危险时，`guard_vision_answer` 会拦截“没有危险/可以走/无障碍”等矛盾结论。

## 输出仲裁

- priority 0：危险停止、感知失效、画面过期；无条件抢占，忽略“自动朗读/引导语音”开关。
- priority 1：引导方向。
- priority 2：唤醒与确认。
- priority 3：VLM/OCR/聊天回答。
- 同一事件同时生成文字与语音；队列上限 16；danger 会清掉尚未播出的普通事件；`cancel` 提升 epoch，晚到的旧音频被丢弃。
- 浏览器通过 `/api/output/stream` SSE 订阅；设备端可将 `OUTPUT_SINK=alsa` 挂到 Piper+aplay。
- 启动时后台预生成常用引导/确认短语（17 条），第一次危险提示也不需要等 Piper 冷启动；缓存上限 50 MB。
- 停止播报不会取消危险检测；后续危险仍可发声。

## 硬件与半双工限制

- 第一阶段语音是半双工：播报期间暂停采集，不支持播报中可靠打断。
- 已提供实体/界面“立即停止播报”控制：页面按钮、语音 `停止播报`、`/api/output/cancel`。
- 全双工需要播放参考信号的回声消除，不能只靠文本相似度过滤。
- 深度/IMU 只有接口和空实现；没有硬件时明确 `available=false`，不伪造距离或倾角。

## 未验证项与剩余限制

1. CM5 真机：Picamera2 双流、CSI 取帧延迟、ALSA 设备号、Piper aarch64、内存峰值、热降频、欠压、8 小时压力。
2. 真机唤醒：真人「小冰小冰」录音、误唤醒/小时、免唤醒窗口、播报回声。
3. 真实引导数据：细柱、椅腿、低矮障碍、窄通道、台阶、道路边界、动态行人；当前分割只有 150 类语义，细物体可能被误判为地面。
4. 状态机参数（0.6 s 帧过期、2.5 s 看门狗、1.5 s 危险保持、4 帧恢复）需要在真机延迟上重新标定。
5. 视觉回答与引导输出的一致性只做了规则守卫，模型本身的危险识别仍依赖分割和 VLM，不能保证。
6. 半双工不能打断；全双工 AEC 未实现。
7. SegFormer-B0 权重为 NVIDIA 非商业许可；Piper 引擎 GPL-3.0、中文音色许可未知；MiniCPM-V 许可需复核。商用前必须替换/确认授权。
8. Flask 仍是开发服务器；SSE 在 waitress/gunicorn 下的缓冲行为未验证。

## 下一阶段建议

1. 在 CM5 上先跑 3 Hz/4 Hz 引导，记录 P50/P95/P99、内存、温度、降频；再跑 8 小时组合压力。
2. 采集真人「小冰小冰」正负样本，标定 `KWS_SCORE/KWS_THRESHOLD`，统计每小时误唤醒与漏唤醒。
3. 采集真实地点/视频批次的引导数据，按批次划分训练/测试，补细柱、椅腿、低矮障碍、窄通道、台阶、道路边界、动态行人。
4. 用同一数据集比较 SegFormer-B0、Fast-SCNN、轻量 MobileNet 分割；先改数据和决策，不盲目换模型。
5. 接入 ToF/双目与 IMU 时，必须做时间同步、视野覆盖和坐标标定；未标定前不报米数与倾角。
6. 全双工需要播放参考信号的 AEC；不要只靠文本相似度。
7. 生产服务替换 Flask 前，验证 SSE 不被缓冲。

# CM5-AI 功能清单

| 项目 | 内容 |
|---|---|
| 适用版本 | v1.3.1（CM5 实机部署后） |
| 整理日期 | 2026-11-02 |
| 运行目标 | Raspberry Pi CM5（4GB），离线本地推理 |
| 依据 | `README.md`、`docs/第二阶段-语音与视觉优化说明.md`、`docs/CM5-实机测试报告-2026-11-02.md`、`app/` 源码 |
| 验证口径 | 「已验证」指 CM5 实机实测或已通过的逻辑测试；「待确认」指需要真人听辨/真实场景；Windows 数据只作对照 |

本项目是面向视障辅助场景的离线多模态服务：摄像头取景 + 语音唤醒 + 语音识别 + 本地大模型理解 + 中文语音播报，另含一套试验性的无盲道引导。

---

## 一、模型能力

全部模型本地推理，不联网。

| 能力 | 模型 | 说明 |
|---|---|---|
| 场景 / 空间 / 图像问答（Windows 开发） | MiniCPM-V 4.7 1B（Q4_K_M + mmproj f16） | llama.cpp 运行，端口 8091 |
| 场景 / 空间 / 图像问答（CM5 默认） | Qwen3-VL-2B-Instruct（Q4_K_M + mmproj-F16） | CM5 实测 MiniCPM 视觉编码 118 s/帧；Qwen 256 px prefill 3.8 s，CM5 默认 |
| 中文 OCR | RapidOCR + PP-OCRv6_small | ONNX det / rec / cls；截图、标牌、说明书、包装等印刷体 |
| 中文语音合成 | Piper zh_CN-huayan-medium | ONNX VITS，22.05 kHz；常驻 worker 一次加载（约 63 MB） |
| 中文语音识别 | Paraformer-zh-small（int8） | 按需加载，闲置后释放 |
| 语音唤醒 | sherpa-onnx-kws-zipformer-wenetspeech-3.3M | 拼音 KWS；唤醒词「小冰小冰」，兼容「小冰」 |
| 无盲道引导分割 | SegFormer-B0 ADE20K | ONNX，384×288 输入，2 线程；输出可走区域与危险类别 |

模型文件不随仓库分发，需要放入 `CM5-AI/models/` 对应目录。Piper 中文音色标注 `License: Unknown`，商用或再分发前需复核授权。

## 二、语音交互功能（默认页签）

| 功能 | 行为 |
|---|---|
| 看前方 | 描述正前方从近到远有什么，带左/中/右与近/远；画面以标牌或文字为主时直接读字，不套用人物车辆模板 |
| 找卫生间 | 只在画面中找卫生间标识，找不到按固定兜底句播报 |
| 找出口 | 找出口标识与箭头方向 |
| 读文字 | 优先走 OCR，使用高清图；无文字再降级 VLM |
| 读日期 | 按生产日期 / 包装日期 / 到期日 / 保质期 / 批号定位；非法值、冲突值、占位语一律拒猜 |
| 详细描述 | 三到五句，比「看前方」更细 |
| 找物品 | 输入物品名，报告位置与遮挡 |
| 聊天 | 不传图，流式生成并逐段播报；无联网查询能力，新闻/天气等实时信息会直接说明 |
| 追问 | 勾选「结合画面」且有当前帧时，带画面与有界历史回答 |
| 停止播报 | 立即停止播放，丢弃未播放句子，旧请求结果不再写回 |
| 语音试听 | 播一句测试语，确认服务端 Piper 是否发声 |
| 比较两样东西 | `compare` 任务，接口与语音意图支持；页面未单独设按钮 |

补充规则：

- 视觉按钮在相机开启时即时抓拍，请求带 `frame_id` / `captured_at`；超过 `FRAME_MAX_AGE`（默认 20 秒）的画面被拒绝并要求重拍。
- 手动上传的静态图标记为「上传」，不会被称为当前视野。
- 追问没有当前帧或帧已过期时，服务端直接返回「当前没有画面，请先拍一张或打开相机」，不调用 VLM。
- 会话历史保留最近 3 轮、最多 360 字，送模型上下文再截到 320 字。
- 每次 VLM 调用记录 `prompt_tokens` / `completion_tokens` / `finish_reason`。

## 三、语音唤醒与语音控制

### 唤醒

- 唤醒词固定为「小冰小冰」，单说「小冰」也能唤醒。
- 只听到唤醒词时回答「我在，请说」，随后 15 秒内可直接说指令，不必重复唤醒词。
- 免唤醒窗口由服务端按 `session_id` 维护；「嗯」「对对对」等确认词不播报、不延长窗口。
- 播报期间暂停采集，播放结束再静默 0.5 秒；VAD 状态在播报前后清空。
- ASR 结果与最近播报文本相似度高时按回声丢弃，并提示「已忽略播报回声」。
- 输入不足 0.6 秒、平均音量过低或 ASR 返回空文本时判为无效语音。
- 同一句指令 2 秒内重复出现只按确认处理。
- 浏览器调试链路先跑专用 KWS（`/api/kws`），模型不可用时退回 ASR 文本匹配；CM5 真机由 `device_voice.py` 用 arecord 常开。

### 语音指令

| 指令 | 行为 |
|---|---|
| 开始引导 / 停止引导 | 启停无盲道引导 |
| 停止播报 | 只取消当前输出队列，不关闭引导 |
| 关闭摄像头 | 引导中同时停止引导，避免继续输出旧方向 |
| 换个话题 / 只聊天 / 不看东西 | 直接走聊天，不触发取图 |
| 引导状态查询 | 服务端快路径返回，不调用 VLM |
| 停一下 / 暂停 | 结合当前状态消歧：只引导则停引导，只播报则停播报，两者同时进行则要求澄清 |
| 否定说法规避 | 如「不要停止引导」按确认处理，不执行停止 |
| 未命中规则 | 返回澄清句「我没听清，请再说一遍」 |

## 四、无盲道引导（试验功能）

| 项目 | 内容 |
|---|---|
| 输出 | 直行 / 向左一点 / 向右一点 / 停下 / 不可用 |
| 服务端循环 | 引导感知在服务端线程运行，浏览器只送帧和显示；CM5 由 Picamera2 直接送帧 |
| 帧管理 | 只有 1 个最新帧槽，处理不过来时覆盖旧帧并计数，不排队积压 |
| 帧率与超时 | 目标 4 fps；帧龄超过 0.6 s 返回 `unavailable/stale`；推理 2.5 s 无心跳触发 `model_stuck` 看门狗 |
| 失效处理 | 超时立即撤销旧直行指令，不沿用最后一次成功结果 |
| 通道分析 | 输入 384×288；softmax 置信度与熵过滤低置信区域；底部 12% 连续可走地面取种子做连通 |
| 分层判断 | 近 / 中 / 远三层，在左 / 中 / 右通道计算连通占比与逐行最大连续宽度；先减边界余量再查瓶颈 |
| 前方物体 | y 0.40–0.85 统计自行车、垃圾桶、桌椅、货架、门、标牌等类别占比；中间 ≥18% 或两侧 ≥10% 时该通道不可通过 |
| 危险优先 | 台阶 / 扶梯 ≥2%、人 ≥8%、道路 ≥15% 立即停 |
| 方向判定 | 近、中通道都合格且远层仍有一定连通才直行；左右都不合格就停，不选「相对最好但仍不合格」的方向 |
| 状态机 | 危险停止立即生效并保持 1.5 s，恢复需连续 4 帧且至少 0.8 s；左右切换需 3 帧和 0.6 s 最小间隔 |
| 输出优先级 | 危险提示 priority 0，绕过普通播报冷却，可抢占普通播报 |
| 标定状态 | 像素宽度未标定，输出 `width_unit=pixel`、`calibrated=false`，不换算厘米 |

**使用方式**：打开摄像头或载入示例图 → 切到「无盲道引导」→ 点「开始引导」。摄像头模式由服务端持续判断，静态图只跑一帧验证阈值。切走页签或关闭浏览器摄像头会停止浏览器送帧模式；设备摄像头模式不受浏览器页签影响。

## 六、系统与工程能力

### 处理链

```text
持续引导：CSI 摄像头 / 浏览器调试帧
  → 最新帧槽 → 质量检查 → 分割置信度/熵
  → 近处种子 + 连通通道 + 分层瓶颈 + 前方物体
  → 状态机 → 输出仲裁 → 短语音 / SSE / ALSA

语音交互：麦克风 → KWS「小冰小冰」→ VAD → ASR
  → 规则意图（控制动作 / 视觉任务 / 聊天 / 未知）
  → 引导快路径 / OCR 快路径 / VLM 慢路径
  → 增量文本 → 语义片段 → 安全守卫
  → SSE 分段 → 常驻 Piper → 连续音频播放
```

### 工程特性

- 引导感知在服务端独立运行，不依赖浏览器持续轮询；普通问答不能阻塞引导，引导运行时 heavy 并发上限降到 1。
- 危险停止与感知失效 priority 0，可抢占普通播报。
- 同一结构化结果生成文字与语音，避免两者冲突。
- 所有帧 / 结果队列有界；过期帧、晚到结果、取消的旧音频会被丢弃。
- 同一回答的多个片段追加播放，不重新启动整段；新回答 / 危险才抢占。
- `done` 不重播全文；SSE 重连按 `Last-Event-ID` 回放，并用 `utterance_id|segment_id` 去重。
- 引导状态查询与 OCR 文本不经过 VLM；视觉问答仍是 prefill 主导的慢路径。
- 真流式输出：`/api/talk` 按语义分段推送 `segment`，最后 `done`。
- 统一输出仲裁：危险抢占、去重、取消。
- 会话按 `session_id` 隔离，有界并带 TTL；换画面只让旧视觉事实失效，聊天历史保留。
- 内存预算默认 3.6GB（4GB 整机减约 0.4GB 系统占用），可用 `MEM_BUDGET_GB` 覆盖。
- 超预算先释放按需加载的 ASR，仍超则 `/api/eyes`、`/api/vlm`、`/api/voice` 返回 503，不做降级输出。
- 页面右上角显示「模型内存 当前 / 预算」与「模型 CPU」，只统计模型侧进程。
- TTS 缓存上限 50MB，超出按时间删最旧；固定短语第二次为 0 ms；启动时后台预生成常用引导 / 确认短语。
- 前端整段回答按 180 字分块合成，当前块播放时提前合成下一块。
- Piper 输出中超过 0.28 s 的停顿压到 0.15 s，句间静音默认 0.12 s。
- 超过 60 字的回答自动提到 1.15 倍速；用户手动语速优先。
- 运行日志：`app.log`（2MB × 3 轮转）、每次启动独立会话目录、`sessions.log`；`/api/metrics` 提供 P50/P95/P99 与失败数。
- 本地安全：VLM 只监听 `127.0.0.1:8091`，启动生成随机 API key，CORS 限定本机页面；网页服务只监听 `127.0.0.1:8090`。
- 启动前预检 `precheck.py`：检查依赖、模型、端口、目录权限，不启动服务、不加载模型、不开相机麦克风。
- 设备端形态：Picamera2 取帧 + ALSA 麦克风 / 喇叭 + 常开语音闭环；支持 `OUTPUT_SINK=alsa` 直接播报。
- 部署支持：ARM64 安装脚本、systemd、健康检查（`/api/health`）、回滚说明。

## 七、主要接口

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/status` | GET | VLM / OCR / ASR / TTS / KWS / 引导 / 输出 / 设备 / 内存 / CPU / 温度状态 |
| `/api/health` | GET | systemd 健康检查，不加载模型 |
| `/api/eyes` | POST | 视觉任务，支持 `scene`、`toilet`、`exit`、`item`、`text`、`date`、`detail`、`compare`、`followup`、`chat` |
| `/api/talk` | POST | SSE 流式对话，逐段返回 `segment`，最后 `done` |
| `/api/voice` | POST | 语音请求：ASR + 意图 + 任务链路；免唤醒窗口由服务端维护 |
| `/api/kws` | POST | 唤醒词检测 |
| `/api/ocr` | POST | 中文 OCR |
| `/api/tts` | POST | 语音合成，`engine=piper` |
| `/api/vlm` | POST | 底层 VLM 调试接口 |
| `/api/guide` | POST | 单帧引导调试 / 回放 |
| `/api/guide/start` / `stop` | POST | 启动 / 停止服务端引导循环 |
| `/api/guide/frame` | POST | 浏览器送帧，只保留最新一帧 |
| `/api/guide/status` | GET | 引导状态、稳定 / 原始方向、指标、帧龄、P50/P95、丢弃数 |
| `/api/metrics` | GET | trace 原始记录、P50/P95/P99、TTS worker 状态 |
| `/api/trace/event` | POST | 客户端补记 `play_start` / `underrun` / `tts_segment_failed` |
| `/api/output/stream` | GET | SSE 推送 `speech` / `cancel`，支持 `Last-Event-ID` 回放 |
| `/api/output/cancel` | POST | 停止普通播报，不关引导 |
| `/api/device/status` | GET | 摄像头、ALSA、设备语音与 sink 状态 |

图片统一使用 `data:image/jpeg;base64,` 形式。

## 八、状态、限制与风险

### 已验证

- Windows 开发机逻辑测试全部通过（v1.1.1 记录为 73 项；v1.3.0 为 176 项）。
- 引导 AI 示例图回放 12/12 通过；危险案例 2，漏检 0，误停 0（Windows）。
- 引导单帧推理 P50 123–129 ms、P95 130–138 ms、最大 151 ms；模型加载约 457 ms；进程内存增量 288.5 MB（Windows）。
- 语义分段首段 12–25 字；Piper 常驻 5 字短句 136 ms（逐次启动 522 ms）（Windows）。
- `/api/talk` 视觉首段 3.6 s / 全文 4.2 s（n=1，Windows 开发机）。
- **CM5 实机**：用户级部署、真实 CSI 摄像头（512×384 lores / 1280×720 still）、XVF3800 录音、ALSA 播放、KWS/ASR/OCR/TTS/VLM 全链路、引导连续 30 分钟（数据见 `CM5-AI/test-runs/`）。
- **CM5 实机**：引导推理 P50 243–316 ms、P95 249–449 ms；VLM `-t3` + 绑 0–2 核后并发无 `model_stuck`。
- **CM5 实机**：取消播报 2 ms（播放中）、停止播报 291 ms、开始引导 98–115 ms、关闭引导 204–477 ms。
- **CM5 实机**：Qwen3-VL-2B 256 px prefill 3.8 s、512 px 9.0 s；MiniCPM 固定 118 s/帧，不可实时。

### 待确认

- 扬声器实际人耳出声、音量、爆音、长句连续性；回环录音未证明 1 kHz 到达麦克风。
- KWS「小冰小冰」真人唤醒率/误唤醒率（合成 TTS 只验证链路）。
- 真实台阶/路缘/玻璃/悬空物、暗光、逆光、遮挡下的引导。
- 真实药品/食品标签日期 OCR；本轮只有屏幕/键盘文本。
- XVF3800 固件/DSP/AEC 实际开关。
- CSI 拔插/重启后的摄像头恢复。
- 8 小时组合运行；本轮只完成 30 分钟连续引导。
- Flask 换 waitress / gunicorn 后 SSE 缓冲行为。

### 已知限制

- 语音入口仍是整段等待 ASR 与推理完成再返回，只有文字聊天是真流式，不能称为完整实时语音。
- 播报期间半双工暂停采集，不支持可靠打断；全双工需要 AEC，当前未实现。
- 无盲道引导只用单目 2D 语义分割，测不到路缘高度、玻璃、悬空物；不支持过马路、上下楼梯或扶梯。
- 站内灰色地面近处可能被判为道路，当前会保守停车；真实细柱、椅腿、低矮障碍仍可能被分割漏掉。
- 多个模型同时运行会争抢四核 CPU；真机导航时 VLM 应保持空闲。
- 日期标签只用构造的 OCR 行与样例图验证，未用真实药品 / 食品标签拍照验证。
- 播报完全依赖服务端 Piper：可执行文件或音色缺失时没有语音。
- Flask 仍是开发服务器，未替换为生产 WSGI。
- ASR Paraformer-small 存在同音误写（杯子/被子、引导/引到、日期/日记），已加同音别名，但真实人声仍需复测。

### 许可风险

- SegFormer-B0 权重为 NVIDIA 非商业许可，商用前需替换。
- Piper 引擎 GPL-3.0，中文音色许可未知，商用分发前必须复核。
- 其余模型许可证需按各自模型卡单独确认。

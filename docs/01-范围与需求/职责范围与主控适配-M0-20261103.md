### 1.2 适配入口与本阶段行为

`app/main_control.py` 是唯一主控请求适配入口，依赖标准库。默认 `MainControlAdapter()` 没有 transport、主机地址或时钟配置，返回 `DEPENDENCY_UNAVAILABLE`，不会采集相机、加载模型或恢复旧引导。

同步 transport 是显式注入的 `callable(request) -> response`，必须自行实施有界 I/O 超时。适配器校验合同版本、来源、证据模式、请求/会话关联、请求期限与握手实例/时钟；拒绝过期场景、序号倒退、无效距离及同帧身份变化。读文件资产需要显式 `asset_roots`，校验租期、大小、SHA256，不删除主控原件。近期帧登记最多 64 条，完整图片/对象会话管理留在 M2。

M0 支持 `capabilities.get`、`scene.query`、`control.intent`、`frame.acquire` 的同步本地适配与测试替身；`target.observation` 仅保留不可用入口。`FixtureTransport` 只回放调用方提供的构造/回放数据，禁止 live。握手数据的 `supported_versions/host_boot_id/clock_source/clock_id/capabilities` 是本地传输封装选择，正式传输需双方对照，不代表主控已部署同名服务。

明确的开始/暂停/继续/结束/重复引导转发允许动作；只接受最终有效话语，否定或含改口的复杂控制先澄清。主控 accepted/pending 不会被说成操作已完成。空间问题不会由图文模型决定通行或补距离。

代码和部署模板默认 `IMAGE_SOURCE=main-control`；`VOICE_SOURCE=device` 不再顺带启动相机，设备语音也不再获得独立相机对象。独立采集仅在显式 `IMAGE_SOURCE=standalone-device-test` 下使用；未连接设备、未改现有板端环境。

启动现有本地测试台后，诊断 `GET /api/main-control/status`，或向 `POST /api/ask` 发送 `{"text":"现在能走吗","session_id":"m0-demo"}`，默认得到明确主控不可用，且不调用 VLM/独立相机。`POST /api/main-control/frame` 接收取图参数，仅返回适配器合同结果；不冒充已经接入实际图像推理。`GET /api/main-control/scene`、`POST /api/main-control/control` 是调试封装，真实协议仍使用合同消息名，不是声称主控已有这些 URL。

### 2.4 实际模型运行器小样

使用已有 MiniCPM-V 4.7 1B Q4_K_M + f16 视觉组件直接请求 llama.cpp，与应用 ASR、会话路由、TTS 和播放器分开测试。CPU 4 线程、context 2048、parallel 1、gpu layers 0；temperature 0.2、top_p 0.9、cache_prompt=false；各题输出上限分别为 128/160/256/128 token。构造文字输入与现有 cats 样图不是用户录音或真人评价。

| 题目 | 首个 content / 完整响应 ms | 结果 |
| --- | ---: | --- |
| 自然聊天 | 433 / 2088 | HTTP 流完成，可接话与追问；尚无独立人工质量评分 |
| 连续追问 | 849 / 2681 | 完成，但把用户的同事处境说成助手经历，记录为质量失败 |
| 详细解释 | 496 / 3876 | 完成；建议示例较泛，不据此宣布详细交流达标 |
| cats 图视觉 | 2989 / 6535 | 描述两只猫等内容，finish_reason=length，在 128 token 截断 |

进程启动到 health=200 约 2537 ms，操作系统文件缓存可能已热，不是断电冷启动。仅该模型进程的 Windows private 观测峰值约 2271 MiB，working set 约 2167 MiB（100 ms 采样）；两者重叠，不能相加，也不是整个交互子系统峰值或 Linux RSS/PSS。该结果已显示当前模型进程对初始资源目标的压力，后续需同题比较较小候选；不能由文件大小推定 RAM，不能靠微调自动降低常驻内存。

这四条是运行路径冒烟，每题只有一次，不报告 P95/P99，不是用户实际说完到有效首声。不能与 CM5、其他平台或不同 context 直接比较。

[构造输入、原样回答和响应结果](../05-测试与验证/m0-runner-cases-20261103.json) 可用于后续同题对照。原始脚本首轮的 SSE 客户端解码失败单独保留，不计模型质量失败；修正客户端后完成上述四题。当前应用服务端本来就按 UTF-8 字节流解码，未发现同类问题。

复现工具 `CM5-AI/MiniCPM-V4.7-1B/tools/m0_runner_smoke.py` 是从本次临时脚本整理的公开版本；不读取主机清单或模型摘要，不采集设备。先用许可已确认且配套的模型启动本地 llama-server（4线程/context2048/parallel1/CPU），再显式提供该运行器地址。下例地址仅指自行启动的本地模型运行器，与主控地址无关：

## 三、待办

### 3.1 尚未验收项

正式主控传输/心跳/重连事件、危险优先级声道、逐段实时事实有效期检查、OutputCancel/PlaybackStatus/InteractionStatus 完整协议、FrameProvider 图像进入 VQA、流式 ASR、常开采集与 AEC 真人插话、完整会话及 OCR 商品关联、模型质量对照与许可闭合、独立质量集、离线包、目标板运行、30 分钟热稳态、整机两小时续航与最终断网包均未通过本阶段验收。

M0 的实时 scene 事实只在 API 中返回，不进入尚不能播放前复查时效的普通音频队列。旧 API 的 spoken 仅沿用已交队列标记，不等于声卡实际出声；真实 PlaybackStatus 留待 M1。模型生成内容的空间事实拦截仍待实现，当前输入分流与提示约束不能充当完整输出校验。

设备语音现仍半双工，会在播报时暂停采集；其修复列入 M1。未测用户实际说完到有效首声、真人插话停声、完整进程峰值、CM5 冷/热性能及续航。代码回归、构造替身或模型文件哈希不证明这些能力通过。

### 3.2 后续顺序与回退

先 M1 流式识别/取消/事件与实际音频闭环，再 M2 图片对象会话、M3 同题模型对照、M4 数字与真人体验；只有真实失败支持时才进行 M5 有限微调及联合验收。微调不作为主要降内存手段。

此阶段在独立 `voice/m0-scope-adapter` 分支提交，修复追加原 PR；主控审查后决定合并。回退可关闭 PR，或合并后 revert 本阶段提交。旧代码有本地基线分支与完整 Git 历史；回退独立设备测试必须保持显式开发模式，不把它当作主控失效处理。
